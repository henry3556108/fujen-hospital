# 網頁補齊（WP2 影像、WP3 結構式、WP4 排程與監控）Implementation Plan

> 分支 `web-pages`；只動 `platform/web/` 與本檔。不改平台 API；API 缺口記在「API 缺口」。每個 Task 一個 commit，測試先行。

**Goal:** 把已完成的 WP2、WP3、WP4 API 接上網頁：共享排程設定、GPU 群組、叢集節點、GPU Dashboard、監控儀表板入口、專案工作列表；影像資料頁（研究、匯入、匯入工作、檔案配對、Accession 清單、PACS 查詢取像）；結構式資料頁（上傳與驗證、預覽與欄位顯示隱藏、描述統計、Target／Feature、前處理、相關矩陣與散佈圖、4 種統計）。補上 TC-A02-07、TC-C02-03、TC-B04-02 的 Playwright 版。

**Architecture:** 沿用 WP1b 外殼：頁面只透過 `useSession().api` 呼叫 Gateway `/api/*`，錯誤用 `ApiErrorAlert`，入口與直接網址阻擋共用 `access/entries.ts`。每個模組自成一個目錄並匯出自己的 `<Routes>`，`App.tsx` 只掛一條 `path/*`。模擬 API（MSW）每個模組一個檔案，狀態掛在 `mockDb()` 物件上（`WeakMap`），`resetMockDb()` 換掉物件後自動回到種子資料，不需要改 `handlers.ts`。模擬資料的形狀取自真實 API（以 `TestClient` 擷取回應後對照）。圖表用自製 SVG 元件（不加相依套件），顏色走 Token。

**Tech Stack:** React 19、react-router 7、MSW 2、Vitest 4、Playwright 1.63（chromium、msedge）。不新增 npm 套件。

## Global Constraints

- 介面文字繁體中文；錯誤訊息同時有 Icon、標題、文字；表格有 `aria-label`、表單欄位有 `<label>`。
- 不寫死色碼：圖表顏色新增 `--primitive-chart-*` → `--color-chart-*` → `--chart-*` 三層 Token，Light／Dark 各自指定；類別色最多 3 個系列（全配對色覺模擬檢查通過的上限），超過時其餘系列只進表格。每張圖都附「表格檢視」。
- 共用檔只做最小、附加式修改：`App.tsx`、`access/entries.ts`、`api/client.ts`（加 `postForm`）、`mocks/server.ts`、`mocks/browser.ts`、`theme/tokens.css`、`styles/app.css`（檔尾附加）。不動 `docs/TODO.md`、路線圖、根目錄 README。
- 權限：頁面依目前專案的權限決定顯示寫入表單或「沒有權限」說明；後端仍是最後一道（403 以行內訊息顯示）。

## API 缺口（不在本分支修改）

1. **欄位顯示／隱藏沒有保存 API**（TC-B04-02）：`/preview?columns=` 只接受「目前可見欄位」。網頁把隱藏狀態存在瀏覽器 localStorage（帳號＋專案＋資料集為鍵），換瀏覽器或電腦不會帶過去。若驗收要求跨裝置一致，需要後端加一個保存端點。
2. **專案 GPU 群組以自由文字輸入**：專案管理頁的「GPU 群組」仍是文字框，未改成從 `/api/admin/gpu-groups` 選（WP1b 的頁面，本分支未動）。
3. **GPU Dashboard 沒有專案名稱**：`/api/admin/cluster/gpu-dashboard` 只回 `project_id`，網頁用 `/api/me` 的專案清單對應名稱。
4. **研究列表不分頁**：`/imaging/studies` 一次回傳全部研究，研究數多時需要後端分頁。
5. **PACS 查詢沒有 Series Description 欄位**：PACS C-FIND 只在 Study 層級，可用欄位為 AccessionNumber、Modality、PatientID、PatientSex、StudyDate、StudyDescription、StudyInstanceUID。

- Playwright 在這台共用開發機上負載高時（load average 超過 30）會有個別等待逾時。新 spec 的等待上限放寬到 15 秒、實際跑幾秒的工作流程測試給 60 秒；逾時的 4 項以 1 個 worker 重跑全部通過。兩個瀏覽器合跑的最後一次為 90 passed、4 failed（全部是 Chromium 逾時，重跑通過）。
- **TC-C02-03 的瀏覽器版未驗證**：kind 叢集裡的 Grafana（13.2.2）記憶體上限 384 MiB，閒置時約 308 MB，瀏覽器登入並載入網頁介面就被 OOMKilled（連續 3 次，其中一次進入 CrashLoopBackOff，約 30 秒後自行恢復，預設儀表板完好、測試儀表板無殘留）。只打 API 的 `platform/acceptance/test_tc_c02.py::test_tc_c02_03_*` 不載入網頁介面，不受影響。修法是把 `platform/deploy/kind/monitoring/grafana.yaml` 的記憶體上限調到 512 MiB 以上，屬於部署設定，本分支沒有改。測試本身（登入、2 種視覺效果、在網頁改更新頻率並勾選「Update default refresh value」儲存、以不帶參數的網址重新開啟後比對）已寫好，選取器取自實際的 Grafana 13 畫面。

### 裁定

- 圖表不加套件，自製 SVG；類別色固定順序、最多 3 個系列（以色覺模擬驗證），第 4 個以後用中性色並靠圖例與表格辨識。每張圖都有表格檢視。
- 模擬狀態在瀏覽器存 sessionStorage，Vitest 不啟用，所以單元測試仍在每個測試後重置。
- jsdom 的 FormData 經 Node fetch 送出會遺失檔名與內容；上傳相關的單元測試改用 Node 內建的 FormData、File（`tests/upload-env.ts`）。
- 「建模管理」仍是 M2 骨架頁，頁內加上「專案工作」連結；「數據管理」改為實頁（`entries.ts` 的 `placeholder` 改為 false）。
