# 網頁補齊（WP2 影像、WP3 結構式、WP4 排程與監控）Implementation Plan

> 分支 `web-pages`；只動 `platform/web/` 與本檔。不改平台 API；API 缺口記在「API 缺口」。每個 Task 一個 commit，測試先行。

**Goal:** 把已完成的 WP2、WP3、WP4 API 接上網頁：共享排程設定、GPU 群組、叢集節點、GPU Dashboard、監控儀表板入口、專案工作列表；影像資料頁（研究、匯入、匯入工作、檔案配對、Accession 清單、PACS 查詢取像）；結構式資料頁（上傳與驗證、預覽與欄位顯示隱藏、描述統計、Target／Feature、前處理、相關矩陣與散佈圖、4 種統計）。補上 TC-A02-07、TC-C02-03、TC-B04-02 的 Playwright 版。

**Architecture:** 沿用 WP1b 外殼：頁面只透過 `useSession().api` 呼叫 Gateway `/api/*`，錯誤用 `ApiErrorAlert`，入口與直接網址阻擋共用 `access/entries.ts`。每個模組自成一個目錄並匯出自己的 `<Routes>`，`App.tsx` 只掛一條 `path/*`。模擬 API（MSW）每個模組一個檔案，狀態掛在 `mockDb()` 物件上（`WeakMap`），`resetMockDb()` 換掉物件後自動回到種子資料，不需要改 `handlers.ts`。模擬資料的形狀取自真實 API（以 `TestClient` 擷取回應後對照）。圖表用自製 SVG 元件（不加相依套件），顏色走 Token。

**Tech Stack:** React 19、react-router 7、MSW 2、Vitest 4、Playwright 1.63（chromium、msedge）。不新增 npm 套件。

## Global Constraints

- 介面文字繁體中文；錯誤訊息同時有 Icon、標題、文字；表格有 `aria-label`、表單欄位有 `<label>`。
- 不寫死色碼：圖表顏色新增 `--primitive-chart-*` → `--color-chart-*` → `--chart-*` 三層 Token，Light／Dark 各自指定；類別色最多 3 個系列（全配對色覺模擬檢查通過的上限），超過時其餘系列只進表格。每張圖都附「表格檢視」。
- 共用檔只做最小、附加式修改：`App.tsx`、`access/entries.ts`、`api/client.ts`（加 `postForm`）、`mocks/server.ts`、`mocks/browser.ts`、`theme/tokens.css`、`styles/app.css`（檔尾附加）。不動 `docs/TODO.md`、路線圖、根目錄 README。
- 權限：頁面依目前專案的權限決定顯示寫入表單或「沒有權限」說明；後端仍是最後一道（403 以行內訊息顯示）。

## Pages

| 路徑 | 頁面 | 權限 | 呼叫的 API |
|---|---|---|---|
| `/admin/scheduling` | 共享排程設定 | Admin | GET／PUT `/api/admin/cluster/shared-scheduling` |
| `/admin/scheduling/groups` | GPU 群組 | Admin | GET／POST `/api/admin/gpu-groups`、PATCH／DELETE `/api/admin/gpu-groups/{name}` |
| `/admin/scheduling/nodes` | 叢集節點 | Admin | GET `/api/admin/cluster/nodes` |
| `/admin/scheduling/gpu-dashboard` | GPU Dashboard | Admin | GET `/api/admin/cluster/gpu-dashboard`、`/nodes` |
| `/admin/scheduling/monitoring` | 監控儀表板 | Admin | 無（連到 Grafana、Prometheus、Alertmanager、Mailpit；位址由 `VITE_GRAFANA_URL` 等設定） |
| `/training/jobs` | 專案工作 | training | GET／POST `/api/projects/{pid}/jobs`、GET `/jobs/{id}`、POST `/jobs/{id}/cancel` |
| `/data/imaging` | 研究列表（5 欄位篩選） | project | GET `/imaging/studies?...` |
| `/data/imaging/studies/:uid` | 研究明細 | project | GET `/imaging/studies/{uid}` |
| `/data/imaging/import` | 匯入 DICOM／NIfTI／ITK／makesense | labeling | POST `/imaging/dicom`、`/imaging/files` |
| `/data/imaging/jobs` | 匯入工作與逐檔結果 | project | GET `/imaging/jobs`、`/imaging/jobs/{id}` |
| `/data/imaging/files` | 非 DICOM 檔案與配對 | project | GET `/imaging/files` |
| `/data/imaging/allowlist` | Accession 清單 | 檢視 project；修改 Admin | GET／PUT `/imaging/accession-allowlist` |
| `/data/imaging/pacs` | PACS 查詢取像 | labeling | POST `/imaging/pacs/query`、`/pacs/retrieve` |
| `/data/tabular` | 資料集列表與上傳 | project | GET／POST `/tabular/datasets`、DELETE `/datasets/{id}`、GET `/datasets/{id}/report` |
| `/data/tabular/:id` | 預覽（欄位顯示／隱藏） | project | GET `/datasets/{id}`、`/preview?columns=` |
| `/data/tabular/:id/describe` | 描述統計與分布 | project | GET `/describe`、`/histogram`、`/value-counts` |
| `/data/tabular/:id/target` | Target 與 Feature | 檢視 project；儲存 training | GET／PUT `/target-feature` |
| `/data/tabular/:id/preprocess` | 前處理 | project | GET `/preprocessing/catalogue`、POST `/preprocess/preview` |
| `/data/tabular/:id/correlation` | 相關矩陣與散佈圖 | project | GET `/correlation`、`/scatter` |
| `/data/tabular/:id/stats` | 4 種統計 | project | POST `/stats/logistic`、`/linear`、`/kaplan-meier`、`/cox` |

影像與結構式 API 的路徑前綴都是 `/api/projects/{pid}`，`pid` 取自外殼的「目前專案」。

## Tasks

1. 共用基礎：`postForm`、`Tabs`、`StatusBadge`、模擬 API 支援（`mocks/support.ts`）、jsdom 下的 multipart 測試可行性。
2. 共享排程設定頁（TC-A02-07）＋排程分頁導覽；取代骨架頁。
3. GPU 群組管理、叢集節點、GPU Dashboard、監控儀表板入口頁。
4. 專案工作列表（送出、輪詢狀態、取消）＋建模管理骨架頁上的連結。
5. 數據管理入口改為實頁（影像／結構式分頁）；影像：研究列表、5 欄位篩選、研究明細。
6. 影像：匯入（逐檔結果）、匯入工作、檔案與配對。
7. 影像：Accession 清單、PACS 查詢取像。
8. 圖表元件與圖表 Token（色覺模擬驗證、表格檢視）。
9. 結構式：資料集列表、上傳與驗證報告、刪除。
10. 結構式：預覽與欄位顯示／隱藏（TC-B04-02）、描述統計與分布。
11. 結構式：Target／Feature、前處理。
12. 結構式：相關矩陣、散佈圖、4 種統計。
13. Playwright：排程、影像、結構式流程與新頁面版面（1280×800、375×812、深色），chromium 與 msedge。
14. Playwright：TC-C02-03 對真 Grafana；README 與本檔「結果」。
