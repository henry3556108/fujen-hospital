# WP7 大型語言模型、RAG、工作流、Wiki 與模型白名單 Implementation Plan

> **For agentic workers:** 依 superpowers:test-driven-development 逐 Task 執行；每個 Task 一個 commit。

**Goal:** 團隊能在平台上完成情境 7 的整條路：經白名單審核取得開源模型、設定量化與資源後載入、上傳 6 種格式文件建立知識庫、在 Playground 以 Free Chat／Chat with Knowledge Base 測試、發布成經 Gateway 授權呼叫的內部 API、用 LangGraph 建多步驟工作流、在 Wiki 維護知識並與 LLM 串接。對應 B-07、B-08 與 D-01 的模型白名單、下載紀錄、遠端程式碼管控。

**Architecture:** `app/llm/` 自成一包。所有外部相依都藏在介面後面，單元測試用記憶體版、整合環境換成真的：

| 介面 | 正式實作 | 本機整合環境 | 單元測試 |
|---|---|---|---|
| `LlmClient`（OpenAI 相容：chat、embeddings） | vLLM | `fake-llm` 容器（Mac 可改指 Ollama） | `InMemoryLlmClient` |
| `ModelSource`（模型來源：查 commit／hash、取檔、是否夾帶程式碼） | 甲方核准的模型來源或離線預載目錄 | `InMemoryModelSource`＋離線預載目錄 | `InMemoryModelSource` |
| `ModelRuntime`（載入／卸載模型） | vLLM Deployment（甲方） | `RecordingModelRuntime`（只記錄設定） | 同左 |
| `VectorStore` | pgvector | pgvector（`pgvector/pgvector:pg16`） | `InMemoryVectorStore`；另有不需外掛的 `SqlVectorStore` |
| `WikiClient` | Wiki.js GraphQL API | Wiki.js 容器 | `InMemoryWiki` |

平台 API 不下載任何模型權重，也不連外部模型站；`ModelSource` 的正式實作留待甲方確認來源後再接。LLM 呼叫一律由平台 API 代為送出並留下 `LlmCallRecord`（請求、回應、脈絡來源 `none｜vector｜wiki_api`），Playground、發布 API、工作流、Wiki 問答共用。

**Tech Stack:** FastAPI、SQLAlchemy 2、httpx、LangGraph 1.2（StateGraph＋MemorySaver）、pypdf；DOCX／HTML／CSV／JSON／TXT 用標準函式庫解析。Wiki.js 2、pgvector（PostgreSQL 16）、`platform/fakes` 的 fake-llm。

## Global Constraints

- 沿用 WP1a：錯誤訊息繁體中文；401／403／404／409／422；測試名稱帶 TC ID；稽核與業務變更同交易。
- 8 類稽核固定不新增：模型下載／刪除／載入／遠端程式碼核准、Playground 對話、發布 API 的發布與呼叫、工作流執行、Wiki 問答 → `inference`；知識庫與文件、Wiki 頁面寫入 → `dataset`；白名單與 Prompt 範本 → `project`。
- 專案範圍 API 一律 `require_project_permission(Permission.CODING)`（與入口「LLM No-code 開發」同一條規則）；白名單、審核、遠端程式碼核准只有 Admin。
- Token 只在送出下載的那一個請求中使用，不寫入資料庫、不寫入稽核、不回傳；只留指紋（SHA-256 前 12 碼）與使用紀錄。
- 逾時與中斷：平台對模型服務的逾時預設 25 秒（`LLM_TIMEOUT_SECONDS`），逾時回 504 `llm_timeout`、連不上回 503 `llm_unavailable`，兩者都帶 `retry: true`；網頁端另設 30 秒上限，保證 30 秒內出現重試提示且輸入框可再用。
- LangGraph／LangChain 的遙測預設關閉（`LANGSMITH_TRACING=false`），不對外連線。
- `main.py` 只加一個 import 與一個 `include_router`；compose 新增服務放 `compose.llm.yaml`。

## API

專案範圍（前綴 `/api/projects/{pid}/llm`，權限 coding）：

| 方法與路徑 | 說明 |
|---|---|
| GET `/models/catalog` | 預載可下載清單（白名單）與安裝狀態 |
| POST `/models/downloads` | 申請下載 `{name}` 或 `{source, repo}`；不在白名單 → 403 並留稽核 |
| POST `/models/downloads/{id}/execute` | 核准後以 `{token}` 執行下載；來源連不上時改離線預載 |
| GET `/models/downloads` | 下載紀錄（commit、hash、時間、使用者、Token 使用紀錄、審核人） |
| DELETE `/models/{name}` | 刪除已下載模型（申請人或 Admin） |
| GET／PUT `/models/{name}/load-config` | 量化（none／4bit／8bit）、CPU、記憶體、GPU 類型與張數 |
| POST `/models/{name}/load`、`/unload` | 載入；夾帶程式碼且未核准 → 403 |
| GET／POST `/prompts`；GET／PATCH／DELETE `/prompts/{id}` | Prompt 範本；`?q=&tag=` 搜尋；個人範本只有本人看得到 |
| GET／PUT `/generation-params` | 7 項生成參數（每人每專案一份） |
| GET／POST `/knowledge-bases`；GET／DELETE `/knowledge-bases/{id}` | 知識庫 |
| POST `/knowledge-bases/{id}/documents`；GET／DELETE `…/documents[/{doc}]` | 上傳文件（多檔）、逐檔結果 |
| POST `/knowledge-bases/{id}/search` | 檢索測試 |
| POST `/chat` | Playground：`{mode: free｜kb, kb_id, message, session_id, prompt_id}` |
| GET `/chat/sessions`、`/chat/sessions/{id}` | 對話紀錄 |
| GET／POST `/services`；GET／PATCH／DELETE `/services/{id}`；PUT `/services/{id}/grants` | 發布為內部服務、授權帳號 |
| GET／POST `/workflows`；GET／PUT／DELETE `/workflows/{id}` | 工作流定義 |
| POST `/workflows/{id}/runs`；GET `/workflows/{id}/runs[/{run}]` | 執行與節點紀錄 |
| GET／POST `/wiki/pages`；GET／PUT／DELETE `/wiki/pages/{id}` | Wiki 文件編輯 |
| GET `/wiki/pages/{id}/history`、`/history/{version}` | 版本與舊版內容 |
| GET `/wiki/search?q=` | 全文檢索（只回本專案的頁面） |
| POST `/wiki/ask` | 以 Wiki API 取文件後交給 LLM |
| GET `/calls`、`/calls/{id}` | LLM 呼叫紀錄 |

Admin（前綴 `/api/admin/llm`）：

| 方法與路徑 | 說明 |
|---|---|
| GET／POST `/whitelist`；DELETE `/whitelist/{name}` | 白名單（來源、repo、commit、sha256、授權、是否需 Token、是否夾帶程式碼） |
| GET `/downloads`；POST `/downloads/{id}/approve`、`/reject` | 審核下載申請 |
| POST／DELETE `/models/{name}/remote-code-approval` | 核准／撤銷執行模型夾帶的程式碼 |

發布服務（經 Gateway `/api/*`）：

| 方法與路徑 | 權限 | 說明 |
|---|---|---|
| POST `/api/llm-services/{slug}/invoke` | 已登入且在該服務授權名單內（或 Admin） | `{question}` 或 `{messages}` → `{answer, sources, usage}`；每次呼叫寫 `inference` 稽核 |

## Tasks

1. 計畫文件（本檔）。
2. `LlmClient`：OpenAI 相容用戶端、記憶體版、逾時與中斷的錯誤型別、7 項生成參數對應。
3. 模型白名單與下載：白名單管理、申請／審核／執行／刪除、離線預載、下載紀錄欄位齊全、Token 不落地。
4. 遠端程式碼管控與載入設定：量化與資源設定保存、未核准不可載入夾帶程式碼的模型。
5. Prompt 範本與生成參數。
6. 文件解析與向量庫：6 種格式、切片、三種 `VectorStore`。
7. 知識庫 API：上傳、逐檔結果、檢索。
8. Playground 對話：Free Chat、Chat with Knowledge Base、對話紀錄、呼叫紀錄、逾時與中斷。
9. 發布 API：發布、授權名單、呼叫、稽核。
10. LangGraph 工作流：定義驗證、組圖、狀態管理、節點紀錄、LLM 串接。
11. Wiki：`WikiClient`、編輯／版本／檢索、Wiki 問答（紀錄顯示走 Wiki API）。
12. 合成文件（`synth documents`）與 S0 smoke：把情境 7 與情境 10 屬於 WP7 的 skip 換成真的步驟。
13. 整合環境：`compose.llm.yaml`、Wiki.js 首次設定、pgvector；經 Gateway 驗收。
14. 網頁：LLM No-code 開發各分頁、Playground；Playwright TC-B07-03、TC-B07-08。
15. 結果與裁定寫回本檔。

## 只能在甲方驗證

- 真實模型下載（對外網路、真實 Token）、權重檔 hash 與授權核對。
- 4-bit、8-bit 量化實際載入（bitsandbytes＋vLLM）與 GPU 類型配置（TC-B07-04）。
- Playground 顯示時間的數字（TC-B07-03）；本機的 fake-llm 不代表真模型速度。
- vLLM 的 `repetition_penalty`、`length_penalty`、`top_k` 是否如預期生效（本機只驗參數送達）。
- 回答品質、檢索正確率不在驗收範圍。
