## 不下載模型的 Smoke Test

可以。架構裡真正需要模型權重的只有 LLM、自動標註和「真的訓練」，而這三處都藏在介面後面，可以換成假實作。這樣就能把整條資料流跑通，驗證的是「架構接得起來」，而不是模型好不好。

| 層級 | 跑什麼 | 需要下載 | 磁碟 |
|---|---|---|---|
| S0 程序內 | 平台 API 加記憶體版假服務，用 pytest 走完 10 個情境的主幹 | 只有 Python 套件 | 約 0.5 GB |

S0 已實作於 `platform/smoke/s0/test_scenarios.py`（`cd platform/smoke && uv run pytest`）。未實作的步驟以 skip 標出所屬工作包，開發完成後把 skip 換成真的步驟。
| S1 容器核心 | PostgreSQL、Keycloak、APISIX、Orthanc、HAPI FHIR、MinIO 加假模型服務 | 容器映像，**不含模型** | 估計 5–8 GB |
| S2 真模型 | Ollama 小模型、MONAI Label、CPU 訓練 | 模型與公開影像 | 數十 GB |

要換成假實作的地方（每一個都是正式程式碼會用到的同一個介面）：

| 介面 | 正式實作 | Smoke 用假實作 | 假實作怎麼做 |
|---|---|---|---|
| LLM（OpenAI 相容 API） | vLLM／Ollama | `fake-llm` | 回傳固定格式的回答並附上收到的 prompt；embedding 用文字雜湊產生固定向量。RAG、Playground、發布 API、LangGraph 全部能跑 |
| 訓練 Job | Keras／scikit-learn 範本 | `fake-trainer` | 睡幾秒、寫出一個隨機初始化的極小模型（本機建立，不下載），讓匯出、部署、推論接得上 |
| 自動標註 | MONAI Label | `fake-autolabel` | 回傳固定的遮罩或框，驗證送出、回存、開啟編輯 |
| 影像資料 | TCIA | 合成 DICOM | 用 pydicom 產生 20 個研究（CT、MR），標頭帶 Accession Number |
| 結構式資料 | Synthea | 合成 CSV | 腳本直接產生 3 × 100 筆與 `bad.csv` |

Smoke 通過的判準：每條資料流都能從頭走到尾、每一步都有稽核紀錄、權限拒絕的情況都擋得住。時間、準確度、量化這類數字不在 smoke 範圍。

不用 Docker 就能先做的：WP1a Task 1–10、WP1b、WP3 的統計與前處理邏輯、WP5 的訓練範本（CPU）、WP7 的白名單邏輯。

## 平行開發的相依關係

```
WP1a Task 1→2→3→4 ─┬─ Track A：Task 5 → Task 9（授權）
                   └─ Track B：Task 6 → 7 → 8 → 10（管理）
獨立、可隨時並行：合成測試資料（platform/tools/synth）、假模型服務（platform/fakes）、WP3 結構式函式庫（platform/libs/tabular）
S0 Smoke 需要：WP1a + 合成資料 + 假服務
```
