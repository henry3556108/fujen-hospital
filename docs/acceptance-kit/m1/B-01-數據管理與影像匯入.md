# B-01 數據管理與醫療影像匯入：驗收示範劇本

本文件給現場操作的專案負責人使用：照著步驟做，對照「預期結果」，把「留存證據」存進中期測試紀錄。共 10 個驗收案例（TC-B01-01～10），案例編號與 `docs/test-cases/acceptance-test-cases.md` 相同。

- 使用資料：`docs/acceptance-kit/m1/data/`（全部是合成資料，說明見 `data/README.md`）。
- 截圖：`docs/acceptance-kit/m1/shots/<案例編號>/`。截圖中的專案名稱是演練時用的 `KIT-B-*`，畫面與文字和正式示範相同，只差專案名稱與工作編號。
- 演練：2026-10-03 已在本機 Kubernetes 平台（網頁 http://localhost:38982）逐步做過一遍，10 個案例的結果都與本文件的預期結果相同。

## 合約指標（附件冊 R2 第 5 節 B-01，驗收方式：測試環境實機操作，比對來源檔案與後台紀錄）

1. 醫療影像批次匯入程式 1 式：匯入 DICOM 研究 20 個，匯入筆數與來源檔案筆數差異 0 筆；支援 NIfTI 影像格式、ITK 影像標註格式與 makesense JSON 標註格式，各匯入 3 筆共 9 筆，解析失敗 0 筆。
2. 影像與標註結果之個別匯入與同時匯入各 3 次，配對後對應至指定專案，配對錯誤 0 筆。
3. 系統本身支援 DICOM 通訊協定並可作為網路節點：與甲方提供之 DICOM 儀器或影像儲傳系統測試介面完成連線與取像測試各 1 次，自本系統送出查詢起 30 秒內接收回應並留存影像與關鍵中繼資料，取得之中繼資料欄位與來源差異 0 筆。
4. 結構式資料 CSV 上傳至訓練專案 3 份共 300 筆，欄位驗證錯誤攔截率 100%、錯誤資料誤放行 0 筆。
5. 新增專案時以 Accession Number 清單 1 份共 10 筆限制可存取影像，清單外影像存取成功 0 次；以 Modality、Patient's Sex、Study Description、Study Date、Series Description 共 5 個欄位各篩選 1 次，回傳結果與篩選條件不符者 0 筆。

另：A-02 規定批次匯入必須是獨立程式，所以影像批次匯入一律用命令列匯入程式（`platform/tools/importer`），不用網頁上傳。

### 3. 終端機（匯入程式）

在可以連到平台 Gateway 的電腦（bash），於 repo 根目錄：

```bash
cd platform/tools/importer
uv sync                                           # 第一次安裝套件
export KIT="$PWD/../../../docs/acceptance-kit/m1" # 資料包位置
export EVID="$HOME/m1-evidence"; mkdir -p "$EVID" # 留存證據的資料夾
export GATEWAY_URL=http://localhost:38980         # 甲方環境改成平台 Gateway 網址
export KEYCLOAK_URL=http://localhost:38180        # 甲方環境改成 Keycloak 網址
```

之後所有指令都在這個終端機、這個目錄執行。每個匯入指令後面的 `| tee …; echo "結束碼 ${PIPESTATUS[0]}"` 會把畫面輸出同時存成檔案，並印出匯入程式的結束碼（0＝全部成功或重複；1＝有檔案失敗或資料夾沒有檔案；2＝未登入、專案錯誤）。

### 4. 模擬 PACS 放入研究（只有用模擬 PACS 時）

甲方環境接的是甲方的 PACS，這一步跳過，改用甲方 PACS 上的測試研究（見 TC-B01-07）。本機演練環境：

```bash
for f in "$KIT"/data/pacs/study_000*/series_001/*.dcm; do
  curl -s -u pacs-admin:pacs-dev -X POST --data-binary @"$f" http://127.0.0.1:38943/instances | grep -o '"Status" : "[A-Za-z]*"'
done
```

每行印出 `"Status" : "Success"`（第一次）或 `"Status" : "AlreadyStored"`（已經放過），共 10 行。

## TC-B01-01 批次匯入需登入

**合約指標**：A-02「批次匯入程式」須登入才能使用（案例判準：未登入執行匯入程式，拒絕並提示登入；不上傳任何檔案）。次數：1 次。

**前置條件**：共同準備完成；P1-lung-ct 沒有匯入工作。

**使用資料**：`data/dicom/`（20 個研究）

**操作步驟**

1. 終端機確認目前沒有登入：
   ```bash
   uv run python -m importer logout
   ```
2. 未登入直接匯入：
   ```bash
   uv run python -m importer upload --project P1-lung-ct --exclude manifest.json "$KIT/data/dicom" 2>&1 | tee "$EVID/TC-B01-01-未登入.txt"; echo "結束碼 ${PIPESTATUS[0]}"
   ```
3. 視窗 B（ra01）：「目前專案」選 `P1-lung-ct` → 左側「數據管理」→「醫療影像」→「匯入工作」分頁。
4. 回終端機登入（device-code，正式做法）：
   ```bash
   uv run python -m importer login
   ```
5. 把終端機印出的網址貼到視窗 B（已登入 ra01）開啟 → 出現「授予 ai-platform-importer 權限」時按「是」（同一帳號通常只在第一次詢問）→ 畫面顯示「裝置登入成功」。

**預期結果**

- 步驟 1 印出 `已登出`。
- 步驟 2 印出 `尚未登入或登入已失效，請先執行：python -m importer login`，`結束碼 2`。（`shots/TC-B01-01/importer-output.txt`）
- 步驟 3「匯入工作」表格顯示「這個專案還沒有匯入工作」：沒有任何檔案被上傳。（`shots/TC-B01-01/01-匯入工作-沒有新增工作.png`）
- 步驟 4 印出 `請用瀏覽器開啟 http://…/realms/ai-platform/device?user_code=XXXX-XXXX，輸入代碼 XXXX-XXXX 完成登入。`，等待中；步驟 5 完成後終端機印出 `已登入`。（`shots/TC-B01-01/02-device-code-授權.png`、`03-device-code-登入成功.png`）

**留存證據**：`$EVID/TC-B01-01-未登入.txt`；步驟 3 的「匯入工作」截圖；步驟 4 終端機畫面（含「已登入」）。

**若結果不符**

- 步驟 2 竟然開始上傳：步驟 1 沒有執行，或設了 `IMPORTER_TOKEN_FILE` 指到別的 token 檔；執行 `uv run python -m importer logout` 後重做。
- 步驟 4 印出「登入失敗：無法啟動 device-code 登入」：`KEYCLOAK_URL` 錯誤或 Keycloak 沒有 `ai-platform-importer` client。
- 步驟 5 登入成了別的帳號：視窗已登入其他人（例如 admin01）時，device-code 會直接用那個帳號。請在 ra01 的 InPrivate 視窗開網址。本機開發環境也可以改用 `echo 'Dev-Passw0rd!' | uv run python -m importer login --username ra01 --password-stdin`（印出 `已登入：ra01`；正式環境關閉此方式）。

## TC-B01-02 DICOM 批次匯入（20 個研究）

**合約指標**：「匯入 DICOM 研究 20 個，匯入筆數與來源檔案筆數差異 0 筆」；另須有「資料集」類稽核紀錄（附件冊 A-03 第 6 項）。次數：20 個研究 1 次。

**前置條件**：TC-B01-01 已登入 ra01；P1-lung-ct 研究列表為「共 0 個研究」。

**使用資料**：`data/dicom/study_0001`～`study_0020`（20 研究、20 序列、100 張影像；`manifest.json` 為來源清單，以 `--exclude` 略過）

**操作步驟**

1. 匯入：
   ```bash
   uv run python -m importer upload --project P1-lung-ct --exclude manifest.json "$KIT/data/dicom" 2>&1 | tee "$EVID/TC-B01-02-匯入.txt"; echo "結束碼 ${PIPESTATUS[0]}"
   ```

2. 核對筆數（與 `data/dicom/manifest.json` 比對）：
   ```bash
   uv run python "$KIT/tools/kit_check.py" counts --project P1-lung-ct | tee "$EVID/TC-B01-02-筆數.txt"
   ```

3. 視窗 B：「數據管理」→「醫療影像」→「研究列表」。
4. 「匯入工作」分頁。
5. 稽核紀錄（後台資料庫，平台沒有稽核查詢畫面）：
   ```bash
   kubectl -n ai-platform exec statefulset/postgres -- psql -U platform -d platform -c \
     "select id, at, actor, category, action, target, result, source_ip, detail from audit_log where category='dataset' and action='imaging.import_dicom' order by id desc limit 5" | tee "$EVID/TC-B01-02-稽核.txt"
   ```

**預期結果**

- 步驟 1：先印 5 行 `匯入工作 #<編號>（dicom，20 檔）`（每 20 檔一批），再列出 100 行檔案，結果全部是 `imported`，最後一行 **`匯入 100、重複 0、失敗 0`**，`結束碼 0`。約 5 秒。（`shots/TC-B01-02/importer-output.txt`）
- 步驟 2：
  ```

  平台專案內（同一批 UID）：研究 20、序列 20、影像 100
  專案內全部研究數：20
  筆數差異：0
  ```
- 步驟 3：**「共 20 個研究，第 1–20 個」**，每列「序列」1、「影像」5；Accession ACC0001～ACC0020 都在，第一列是 2024-02-19 ACC0013。（`shots/TC-B01-02/01-研究列表-20個研究.png`）
- 步驟 4：5 筆工作，「來源」DICOM 上傳、「結果」全部成功、「檔案數」匯入 20、重複 0、失敗 0、「建立者」ra01。（`shots/TC-B01-02/02-匯入工作.png`）
- 步驟 5：5 筆 `ra01 | dataset | imaging.import_dicom | project:<P1 編號> | success | <來源 IP> | {"job_id": …, "counts": {"imported": 20, "duplicate": 0, "failed": 0}}`，含誰、何時、類別、動作、對象、結果、來源 IP。（`shots/TC-B01-02/audit-dataset.txt`）

**留存證據**：`$EVID/TC-B01-02-匯入.txt`、`-筆數.txt`、`-稽核.txt`；研究列表與匯入工作截圖。

**若結果不符**

- 出現 `重複 100`：P1 先前已匯入過同一批（例如自測），改用 `M1-imaging`（見共同準備）。
- `找不到專案或你不是成員：P1-lung-ct`：登入的不是 ra01，或 ra01 不是 P1 成員。
- 有 `failed`：看該行原因欄。若原因是 `HTTP 413`（一次上傳太大），加 `--batch-size 5` 重試。
- 研究數不是 20：確認「目前專案」選的是 P1-lung-ct；P1 若設了 Accession 清單只會顯示清單內的研究（「Accession 清單」分頁應為「未設定清單」）。
- `kubectl` 不能用：甲方環境請系統管理員以資料庫帳號執行同一句 SQL。

## TC-B01-04 影像與標註配對（同時匯入 3 次、個別匯入 3 次）

**合約指標**：「影像與標註結果之個別匯入與同時匯入各 3 次，配對後對應至指定專案，配對錯誤 0 筆。」次數：同時 3 次＋個別 3 次。

**前置條件**：已建立 `M1-pair-together`、`M1-pair-separate`，兩者都沒有檔案；ra01 已登入匯入程式。

**使用資料**：`data/nifti/`、`data/itk/`、`data/pairing/makesense_with_dicom/`（makesense 3 份＋研究 1～3 的 15 張 DICOM）

**操作步驟**

同時匯入（影像與標註在同一次指令）：專案 `M1-pair-together`

1. 第 1 次 NIfTI：
   ```bash
   uv run python -m importer upload --project M1-pair-together --exclude manifest.json "$KIT/data/nifti" 2>&1 | tee "$EVID/TC-B01-04-同時1.txt"
   ```
2. 第 2 次 ITK：
   ```bash
   uv run python -m importer upload --project M1-pair-together --exclude manifest.json "$KIT/data/itk" 2>&1 | tee "$EVID/TC-B01-04-同時2.txt"
   ```
3. 第 3 次 makesense＋DICOM：
   ```bash
   uv run python -m importer upload --project M1-pair-together "$KIT/data/pairing/makesense_with_dicom" 2>&1 | tee "$EVID/TC-B01-04-同時3.txt"
   ```
4. 視窗 B：「目前專案」選 `M1-pair-together` →「醫療影像」→「檔案與配對」。

個別匯入（先匯標註、後匯影像，分兩次指令）：專案 `M1-pair-separate`

5. 3 種標註先匯入：
   ```bash
   uv run python -m importer upload --project M1-pair-separate --exclude manifest.json --exclude '*_image*' "$KIT/data/nifti" 2>&1 | tee "$EVID/TC-B01-04-個別1-標註.txt"
   uv run python -m importer upload --project M1-pair-separate --exclude manifest.json --exclude '*_image*' "$KIT/data/itk"   2>&1 | tee "$EVID/TC-B01-04-個別2-標註.txt"
   uv run python -m importer upload --project M1-pair-separate --exclude '*.dcm' "$KIT/data/pairing/makesense_with_dicom" 2>&1 | tee "$EVID/TC-B01-04-個別3-標註.txt"
   ```
6. 視窗 B：「目前專案」選 `M1-pair-separate` →「檔案與配對」。
