- 甲方提供的 Windows 電腦，安裝 Chrome 與 Edge 穩定版。記下版本（網址列輸入 `chrome://version`、`edge://version`）。
- 視窗最大化；Windows「顯示 › 縮放」維持建議值（通常 100% 或 125%），瀏覽器縮放 100%（Ctrl+0）。

**使用資料**：admin01（第 1 頁在登入前看）。

| 7 | 影像標註 | `/labeling` | 研究清單、「以 CSV 診斷結果自動分類標註」表單 |

**操作步驟**（先 Chrome，再 Edge，各做一次）：

1. 開瀏覽器，到第 1 頁，截圖。按「登入」，以 admin01 登入。
2. 確認「目前專案」是 P1-lung-ct。
3. 依序在網址列輸入第 2 到 10 頁的網址。每一頁：等內容出現 → 截圖 → 依「破版判定」逐項看 → 在表格的「確認可操作的元件」各點一下（下拉選單打開即可，不要送出表單）。
4. 在紀錄表每頁寫「破版：無／有（說明）」「無法操作：無／有（說明）」。

**破版判定**（任一項成立即算破版）：
- 頁面出現水平捲軸（內容比視窗寬）。
- 文字、按鈕或表格欄位互相重疊，或被裁切看不完整（表格本身可橫向捲動的除外）。
- 左側選單、上方標題列（目前專案、色彩主題、帳號、登出）跑位、換行擠成多行或消失。
- 中文字顯示為方框或亂碼。
- 按鈕、輸入框、下拉選單的外框或文字明顯錯位、看不到。
- 「無法操作」：按鈕按了沒反應、下拉打不開、輸入框不能輸入。

**預期結果**：Chrome 10 頁、Edge 10 頁，破版 0 頁、無法操作 0 項。開發環境以程式在 1366×768 檢查（水平捲軸、超出視窗的元素、Console 錯誤）兩個瀏覽器都是 0（參考截圖：[Edge 專案頁](shots/TC-A02-08/Edge-專案.jpg)、[Chrome 描述統計](shots/TC-A02-08/Chrome-描述統計.jpg)）。

**留存證據**：20 張截圖（瀏覽器名稱與版本要入鏡，可先開 `chrome://version` 截一張）；紀錄表 20 列。

**若結果不符**：記下瀏覽器版本、視窗大小、Windows 縮放比例、頁面網址與截圖，列為一般缺陷。開發機上可用 `cd platform/web && npx playwright test e2e/pages-layout.spec.ts --project=msedge` 重現（需安裝 Edge）。

**合約指標**：第 4 節「主要頁面（登入、專案清單、資料清單、影像檢視器、訓練任務清單、監控看板）首屏載入平均 5 秒以內、最慢一次 10 秒以內；管理後台列表頁平均 5 秒以內、最慢一次 10 秒以內；介面資料回應平均 3 秒以內、最慢一次 8 秒以內；以上各量測 3 次……於測試資料基線、同一機房或有線網路環境、頁面第二次載入時量測」。

> **暫行做法**：自動量測腳本（6 個主要頁面首屏、管理列表頁、介面回應，各量 3 次並產出報表）尚未完成，預定由 `platform/web/e2e` 的量測腳本取代本節的人工步驟。腳本完成前，現場以下列人工方法量測。

- 甲方 Windows 電腦以有線網路連到測試環境；Chrome 穩定版（另以 Edge 重複一次可作為補充）。
- 測試資料基線已匯入（P1 有 20 個 DICOM 研究、結構式資料 3 份）。
- 以 admin01 登入，「目前專案」P1-lung-ct。

## TC-SS-02 未登入不可存取（API）

**合約指標**：測試案例「不帶 token 呼叫 10 個受保護 API（含管理頁 API），成功 0 次，全部回 401」。

**前置條件**：知道 P1 的專案編號（`tools/tc-a02-04-cross-project-api.sh` 第一行會印出；開發環境為 38）與 P2 的編號（開發環境 39）。

**使用資料**：無 token。

**操作步驟**：在終端機執行（把 38、39 換成實際編號）：

```bash
for p in /api/me /api/admin/users /api/admin/projects /api/admin/projects/38/members /api/admin/gpu-groups \
         /api/admin/cluster/nodes /api/admin/cluster/shared-scheduling /api/projects/38/imaging/studies \
         /api/projects/39/tabular/datasets /api/projects/38/jobs; do
  echo "$(curl -s -o /dev/null -w '%{http_code}' ${GATEWAY:-http://localhost:38980}$p) $p"
done
```

**預期結果**：10 行都是 `401`；單獨執行 `curl -s http://localhost:38980/api/admin/users` 回 `{"detail":"未登入"}`。對照：同樣 10 個網址帶 admin01 的 token 都回 200（實測如此，代表網址正確）。

**留存證據**：輸出存成 `TC-SS-02.txt`。

**若結果不符**：任何一行不是 401 屬阻斷級缺陷。

## TC-SS-03 偽造與過期 token

**合約指標**：測試案例「用錯誤簽章、過期、別的 issuer 的 token 各呼叫 3 次，成功 0 次」。

**前置條件**：演練電腦有 `curl` 與 `openssl`。過期 token 要先存一張、等 6 分鐘（Keycloak access token 有效 300 秒），**請在驗收開始時先做步驟 1**。

**使用資料**：vw01；指令稿 [`tools/tc-ss-03-forged-tokens.sh`](tools/tc-ss-03-forged-tokens.sh)。

**操作步驟**：

1. 驗收一開始執行：`bash docs/acceptance-kit/m1/tools/tc-ss-03-forged-tokens.sh save-expired`（取得 vw01 的真 token 存檔，並印出取得時間）。
2. 執行：`bash docs/acceptance-kit/m1/tools/tc-ss-03-forged-tokens.sh forge`。指令稿先用真 token 打一次 `/api/me`（對照組，應 200），再：
   - 錯誤簽章：內容不變，改用另一把自產私鑰簽章，打 3 次；
   - 別的 issuer：把 `iss` 改成 `https://evil.example.com/realms/ai-platform` 並用自產私鑰簽，打 3 次。
3. 步驟 1 之後至少 6 分鐘，執行：`bash docs/acceptance-kit/m1/tools/tc-ss-03-forged-tokens.sh expired`（用存檔的過期 token 打 3 次）。

**預期結果**（實測輸出）：

```
對照組（真的 token）：HTTP 200（應為 200）
錯誤簽章 第 1 次：HTTP 401 {"detail":"登入已失效，請重新登入"}
錯誤簽章 第 2 次：HTTP 401 ...
錯誤簽章 第 3 次：HTTP 401 ...
別的 issuer 第 1 次：HTTP 401 ...
別的 issuer 第 2 次：HTTP 401 ...
別的 issuer 第 3 次：HTTP 401 ...
```
