## 驗收前準備

1. **網址與帳號**：腳本以開發環境的網址為例（網頁 `http://localhost:38982`、Gateway `:38980`、Keycloak `:38180`）。到甲方環境請換成實際網址。
   帳號為種子資料的 8 個測試帳號；密碼為開發用值，甲方環境請以實際設定為準，並與驗收申請附的帳號清單一致。
2. **乾淨基線**：驗收前跑一次種子資料（`deploy.sh` 的 seed 工作），確認 3 個專案、8 個帳號，P1-lung-ct 沒有影像。
3. **瀏覽器**：Windows 版 Chrome 與 Edge 各一，另備一個 InPrivate／無痕視窗（B-01 匯入程式登入用）。
4. **終端機**：可執行 `kubectl`、`uv` 的電腦，A-01、C-01、C-02 與部分 B-01、通用條件的檢查要用。
5. **證據資料夾**：每個案例建一個資料夾，依腳本「留存證據」存截圖與輸出，之後彙整成《中期測試紀錄》。

## 建議操作順序

有些案例依賴前面建立的資料，依這個順序最順：

1. **A-01**（環境與底層庫）：先證明環境就緒。
2. **通用條件的 TC-SS-01～05**（登入、未登入、偽造 token、金鑰、繞過 Gateway）。
3. **A-03**（帳號、角色、權限）：TC-A03-06、07 會改種子帳號的權限與成員資格，腳本內含還原步驟，**做完務必還原**再往下（TC-A03-08 用演練帳號 `KIT-A-pw`，不動種子帳號）。
4. **B-01**（影像匯入）：TC-B01-02 把 20 個研究匯入 P1，之後 A-02 的影像標註入口才有內容。
5. **B-04**（結構式資料）。
6. **A-02**（入口、多人同時操作、GPU 模式、共享排程設定、瀏覽器相容、首屏時間）。
7. **C-01**（GPU 與伺服器管理）：TC-C01-07 新增節點屬破壞性步驟，放在最後。
8. **C-02**（監控）：TC-C02-04 會讓節點暫時失聯與 CPU 滿載，放在最後。
9. **TC-A03-09、TC-SS-06、07**（稽核抽查與稽核不可修改）：前面的操作都會產生稽核，最後一起抽查。

## 已知問題（不影響判定，但現場可能被問到）

各腳本最後都有已知問題表。跨腳本的重點：

- 稽核紀錄的來源 IP 在開發叢集顯示為節點位址（172.19.0.x），不是使用者電腦；修正已完成但待確認後合併，甲方環境需確認負載平衡器傳遞真實來源位址。
- 工作通常 1 秒內就開始執行，畫面不一定看得到「排隊中」；以「建立時間早於開始時間」作為曾排隊的證據。
- 新開分頁會要求再按一次「登入」（單一登入，不必再輸入密碼）；建議在同一分頁切換頁面。
- 稽核紀錄頁的時間以瀏覽器時區顯示，資料庫存的是 UTC。
- 已修正（2026-10-04）：專案成員頁載入現有成員、稽核紀錄查詢頁、標註群組與 Dashboard、稽核表資料庫權限、工作時間改用叢集時間、內部訊息不再顯示、CSV 列號從 1 起算、PACS 回應時間、散佈圖點數、監控覆蓋與 3 條告警規則。
