# M1 驗收操作劇本：A-03 帳號、角色與權限管理

對象：驗收當天現場操作的專案負責人。網址、帳號、登入方式、同時登入多帳號的做法見《[A-02 核心入口與網頁介面](A-02-核心入口與網頁介面.md)》的「共同說明」。

## 本模組的注意事項

- 新建的專案與帳號一律以 `KIT-A-` 開頭（例：`KIT-A-p1`、`KIT-A-u1`），演練結束時刪除。
- **TC-A03-06、07 會暫時改動種子帳號**（ra01 的權限、md01 的成員資格）。TC-A03-08 改用演練帳號 `KIT-A-pw`，不動種子帳號。每案最後都有「還原」步驟，**一定要做完並截圖**，否則後面的案例與其他人的測試都會出錯。
- 「專案成員」頁目前**不會讀出帳號現有的角色與權限**：選了帳號後，角色欄永遠先顯示「Viewer」、權限是 Viewer 預設。直接按「儲存成員設定」會把該帳號改成 Viewer。**每次都要先選對角色，再改權限**（見本文末「發現的問題」第 3 項）。
- 成功訊息都在頁面上方綠色框，格式為「完成：<訊息>」（例：「完成：已新增專案「KIT-A-p1」」，[截圖](shots/TC-A03-01/新增成功訊息.jpg)）。下文只寫「<訊息>」部分。
- 稽核紀錄目前**沒有網頁頁面或 API 可以查看**，只能在資料庫查詢（唯讀）。查詢指令統一如下（開發環境 Kubernetes；甲方環境換成對應的 Pod 名稱）：

```bash
# 最近 20 筆稽核（誰、何時、類別、動作、對象、結果、來源 IP）
kubectl -n ai-platform exec postgres-0 -- psql -U platform -d platform -c \
  "select id, actor, at, category, action, target, result, source_ip from audit_log order by id desc limit 20;"
```

## TC-A03-01 專案 CRUD

**合約指標**：「網頁式帳號與專案管理：建立專案 3 個……新增、修改、刪除各 3 次成功率 100%；Admin 可新增、管理、刪除專案……各 1 次成功」；A-03 第 6 項「專案……之操作均產生稽核紀錄」。次數：新增 3、修改 3、刪除 3。

**前置條件**：以 admin01 登入；「帳號管理 › 專案」列表中沒有 `KIT-A-p1` 到 `KIT-A-p3`。

**使用資料**：admin01；專案名稱 `KIT-A-p1`、`KIT-A-p2`、`KIT-A-p3`。

**操作步驟**：

1. 點左側「帳號管理」（預設在分頁「專案」）。截圖專案列表（[截圖](shots/TC-A03-01/專案清單.jpg)）。
2. 捲到下方「新增專案」：「專案名稱（必填）」輸入 `KIT-A-p1`，「說明」輸入 `驗收示範 1`，「GPU 群組」保留「不綁定」，按「新增專案」。
3. 重複步驟 2，名稱 `KIT-A-p2`、說明 `驗收示範 2`。
4. 重複步驟 2，名稱 `KIT-A-p3`、說明 `驗收示範 3`。截圖列表。
5. 在列表 `KIT-A-p1` 那一列按「編輯」。下方表單標題變成「編輯專案」（[截圖](shots/TC-A03-01/編輯專案表單.jpg)），把「說明」改成 `驗收示範 1（已修改）`，按「儲存」。

7. 在 `KIT-A-p1` 那一列按「刪除」，跳出「刪除專案」確認視窗，按「確認刪除」。
8. 對 `KIT-A-p2`、`KIT-A-p3` 重複步驟 7。截圖列表。

## TC-A03-02 帳號 CRUD

**合約指標**：「帳號 8 個，新增、修改、刪除各 3 次成功率 100%」；A-03 第 6 項帳號操作產生稽核紀錄。本案例另驗 Keycloak 同步（新帳號可登入、刪除後不能登入）。

## TC-A03-03 非 Admin 不可管理帳號

**合約指標**：低權限越權嘗試「越權成功 0 次，提示顯示率 100%」；本案例：pi01、user01 各嘗試新增帳號 5 次，成功 0 次，介面顯示無權限提示。

**前置條件**：無。

**使用資料**：pi01、user01。

**操作步驟（網頁）**：

1. 開無痕視窗，以 pi01 登入。確認左側選單沒有「帳號管理」。
2. 在網址列輸入 `http://localhost:38982/admin/users`，按 Enter。截圖。
3. 依序再輸入 `/admin/projects`、`/admin/members` 兩個網址（前面加 `http://localhost:38982`）。
4. 登出，改以 user01 登入，重複步驟 1 到 3。

**操作步驟（API，各 5 次新增帳號）**：

5. 在終端機執行（把 `<帳號>` 依序換成 `pi01`、`user01`）：

```bash
TOKEN=$(curl -s -X POST http://localhost:38180/realms/ai-platform/protocol/openid-connect/token \
  -d grant_type=password -d client_id=ai-platform-web -d username=<帳號> --data-urlencode password='Dev-Passw0rd!' \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
for i in 1 2 3 4 5; do
  curl -s -w '  HTTP %{http_code}\n' -X POST http://localhost:38980/api/admin/users \
    -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
    -d "{\"username\":\"KIT-A-x$i\",\"password\":\"Kit-A-Init-2026!\",\"account_type\":\"admin\"}"
done
```

6. 以 admin01 打開「帳號管理 › 帳號」，確認沒有 `KIT-A-x1` 到 `KIT-A-x5`。

**預期結果**：
- 網頁：每個網址都顯示「無法存取此功能」「「帳號管理」需要 Admin 帳號類型，你的帳號類型是 User。」「如需使用，請聯絡專案負責人或系統管理者調整權限。」與「回首頁」按鈕（[截圖](shots/TC-A03-03/pi01-帳號管理無權限.jpg)）。2 帳號 × 3 網址 = 6 次，全部顯示提示。
- API：10 行都是 `{"detail":"需要 Admin 權限"}  HTTP 403`（實測如此）。
- 步驟 6：列表仍是原本的帳號，沒有 `KIT-A-x` 開頭的帳號。成功 0／10。

**留存證據**：6 張網頁截圖；API 輸出存成 `TC-A03-03-api.txt`；步驟 6 列表截圖。

**若結果不符**：
- 回 201 並建立了帳號：阻斷級缺陷；立即以 admin01 刪除 `KIT-A-x` 帳號。
- 回 401：token 取得失敗（`TOKEN` 是空的），檢查密碼。
