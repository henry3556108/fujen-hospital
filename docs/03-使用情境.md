# 需求與使用情境

## 情境 1：開一個研究專案

**角色**：Admin、Principal Investigator

PI 要啟動一個肺部 CT 研究。管理者建立專案、帳號與角色，限定這個專案只能看特定檢查的影像，並指定用哪一群 GPU 訓練。

**操作步驟**

1. 建立專案、帳號，指派角色與 5 類權限（A-03 帳號、角色與權限管理）
2. 用 Accession Number 清單限制可存取的影像（B-01 數據管理與醫療影像匯入）
3. 指定此專案使用的 GPU 群組（C-01 多台 GPU／CPU 伺服器管理）
4. 成員登入後只看到自己權限內的入口（A-02 核心入口與網頁操作介面）

**驗收時會實測**

- 權限設定 10 秒內生效
- 越權操作 10 次成功 0 次
- 清單外影像存取成功 0 次
- 跨專案存取他人資料成功 0 次

## 情境 2：把影像帶進平台

**角色**：Research Assistant

研究助理從院內影像儲傳系統查詢並取回影像，也把手上既有的 NIfTI 與舊標註一次匯入，再依條件篩出要用的影像。

**操作步驟**

1. 透過 DICOM 網路節點向影像儲傳系統查詢與取像（B-01 數據管理與醫療影像匯入）
2. 以批次匯入程式匯入 DICOM、NIfTI、ITK、makesense 標註（B-01 數據管理與醫療影像匯入）
3. 影像與標註自動配對到專案（B-01 數據管理與醫療影像匯入）
4. 以 Modality、Study Date 等 5 個欄位篩選（B-01 數據管理與醫療影像匯入）

**驗收時會實測**

- 送出查詢後 30 秒內收到回應
- DICOM 20 研究筆數差異 0
- 配對錯誤 0 筆

## 情境 3：醫師標註影像

**角色**：Medical Doctor

醫師打開研究，調窗位看病灶，做分類、分割或框選標註；量大的部分先丟給自動標註工具，醫師只要審核修正。

**操作步驟**

1. 開啟研究，調整 WW/WC、旋轉、排列，用快捷鍵（B-02 影像標註平台）
2. 執行分類、分割、物件偵測標註並評分（B-02 影像標註平台）
3. 送出自動標註，結果回存平台（B-03 自動標註整合）
4. 在標註平台開啟自動標註結果並修正（B-02 影像標註平台）

**驗收時會實測**

- 30 筆標註儲存 100%，重載差異 0
- 自動標註回傳後 30 秒內顯示
- 不驗自動標註的正確率

## 情境 4：不寫程式訓練模型

**角色**：Research Assistant、Coder Assistant

標完後直接挑訓練型態、切分資料、設定增強與超參數，送出後任務自動排隊上 GPU。需要微調時，匯出程式碼改完再跑。

**操作步驟**

1. 選訓練種類、影像範圍、Label、Resize、資料切分（B-05 自動訓練與模型匯出）
2. 設定資料增強 6 項與超參數，儲存設定（B-05 自動訓練與模型匯出）
3. 送出訓練，進入佇列並分配到 GPU（C-01 多台 GPU／CPU 伺服器管理）
4. 查看訓練紀錄，匯出 pkl 或 Keras H5（B-05 自動訓練與模型匯出）
5. 匯出原始碼，修改後再執行（B-05 自動訓練與模型匯出）

**驗收時會實測**

- 5 種訓練任務建立 100%
- 設定重現差異 0 筆
- 匯出模型能在平台外用 Python 呼叫

## 情境 5：部署模型給別人用

**角色**：Principal Investigator、Viewer

模型訓練好後，PI 先對測試集跑一次批次推論，再部署成線上服務，只開放給特定帳號即時呼叫。

**操作步驟**

1. 選訓練完成的模型做批次推論（B-06 模型部署與推論服務）
2. 檢視結果：表格自動新增預測欄、影像顯示結果（B-06 模型部署與推論服務）
3. 部署為線上服務並設定可用帳號（B-06 模型部署與推論服務）
4. 授權帳號即時推論，查歷史紀錄並下載結果（B-06 模型部署與推論服務）

**驗收時會實測**

- 授權呼叫 10 次成功 100%
- 未授權呼叫 10 次成功 0 次
- 推論歷史抽查 10 筆缺漏 0

## 情境 6：分析結構式臨床資料

**角色**：Research Assistant、Principal Investigator

研究者上傳一份病人資料 CSV，看分布與相關性，做前處理後跑存活分析，必要時直接拿去訓練分類或迴歸模型。

**操作步驟**

1. 上傳 CSV，系統驗證欄位（B-01 數據管理與醫療影像匯入）
2. 看描述統計、分布、相關矩陣（B-04 結構式資料與醫學統計）
3. 設 Target 與 Feature，補值、One Hot（B-04 結構式資料與醫學統計）
4. 執行 Logistic、Linear、Survival、Cox 分析（B-04 結構式資料與醫學統計）
5. 以同份資料訓練分類或迴歸模型（B-05 自動訓練與模型匯出）

**驗收時會實測**

- 錯誤資料攔截 100%
- 4 種統計各產出圖表，失敗 0
- 前處理方法不少於 50 種

## 情境 7：建一個院內知識問答

**角色**：Coder Assistant

團隊想用本地 LLM 回答作業規範問題。先下載並量化載入模型，上傳文件建成知識庫，在 Playground 測試，再發布成 API 給其他系統用；複雜流程用 LangGraph 串起來。

**操作步驟**

1. 經白名單審核下載開源模型（D-01 軟體來源與資安合規）
2. 以 4-bit 或 8-bit 量化載入，設定資源（B-07 大型語言模型與 RAG）
3. 上傳 6 種格式文件建立向量庫（B-07 大型語言模型與 RAG）
4. 在 Playground 以 Chat with Knowledge Base 測試（B-07 大型語言模型與 RAG）
5. 發布為內部服務 RESTful API（B-07 大型語言模型與 RAG）
6. 用 LangGraph 建多步驟工作流、在 Wiki 維護知識（B-08 LangGraph 工作流與 Wiki 知識庫）

**驗收時會實測**

- 白名單外下載成功 0 次
- RAG 寫入失敗 0 份
- API 外部呼叫 3 次成功
- 不驗回答正確率

## 情境 8：醫療資料標準化交換

**角色**：資訊人員

院內 HIS 資料、HL7 V2 訊息與生理監視器數據要轉成 FHIR，外部系統只能經 Gateway、以 OAuth2 身分存取，所有存取都有審計紀錄。

**操作步驟**

1. 接入 SQL、CSV、HL7 V2、JSON 來源（C-03 HL7 FHIR 醫療資料交換平台）
2. 以對應工具建立 FHIR 轉換規則（C-03 HL7 FHIR 醫療資料交換平台）
3. 設定定時抓取、轉換、轉存排程（C-03 HL7 FHIR 醫療資料交換平台）
4. 生理監視器資料即時轉成 Observation（C-03 HL7 FHIR 醫療資料交換平台）
5. 外部系統經 API Gateway 與 OAuth2 存取（C-03 HL7 FHIR 醫療資料交換平台）

**驗收時會實測**

- FHIR Validator 不通過 0 筆
- 繞過 Gateway 成功 0 次
- 他租戶存取成功 0 次
- 排程偏差 5 分鐘內

## 情境 9：維運與算力調度

**角色**：Admin

管理者每天看 GPU 被誰占用、系統資源是否吃緊；異常時收到告警。需要擴充時，把新伺服器加進來。

**操作步驟**

1. 在 GPU Dashboard 看每張卡跑的專案與使用者（C-01 多台 GPU／CPU 伺服器管理）
2. 在監控儀表板看節點、Pod、CPU、記憶體、GPU（C-02 系統監控工具）
3. 收到異常告警，重複告警自動抑制（C-02 系統監控工具）
4. 新增伺服器納管，調整群組與負載平衡（C-01 多台 GPU／CPU 伺服器管理）
5. 底層環境依部署及還原說明維護（A-01 平台環境與底層庫建置）

**驗收時會實測**

- Dashboard 顯示差異 0
- 告警送出 100%，重複 0
- 佇列順序不符 0、任務遺失 0

## 情境 10：資安稽核與合規

**角色**：Admin、資安人員

稽核單位要確認平台用了哪些開源元件、模型從哪裡來、誰在什麼時候做了什麼操作。

**操作步驟**

1. 核對第三方軟體與模型授權清單（D-01 軟體來源與資安合規）
2. 檢視模型下載審核紀錄（hash、commit、審核人）（D-01 軟體來源與資安合規）
3. 確認遠端程式碼預設被阻擋（D-01 軟體來源與資安合規）
4. 抽查 8 類稽核紀錄（D-01 軟體來源與資安合規）
5. 執行掃毒（D-01 軟體來源與資安合規）

**驗收時會實測**

- 授權清單差異 0 項
- 8 類稽核共 24 筆缺漏 0
- 惡意程式 0 件
