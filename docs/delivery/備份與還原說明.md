# 備份與還原說明

腳本在 `platform/compliance/scripts/`，以環境變數 `COMPOSE_PROJECT`（預設 `ai-platform`）與 `COMPOSE_OVERLAYS`（疊加檔，空白分隔）指定對象。

## 備份內容

| 對象 | 方式 | 檔案 |
|---|---|---|
| PostgreSQL 所有資料庫（平台、Keycloak） | `pg_dump -Fc`，每個資料庫一份；另備份角色 | `postgres/<資料庫>.dump`、`postgres/roles.sql` |
| 物件儲存（MinIO） | 由平台 API 容器以它自己的最小權限帳號匯出所有物件 | `objects.tar` |
| 檔案型 volume（Orthanc 影像、本機物件目錄等） | 暫停使用該 volume 的服務後打包 | `volumes/<volume>.tar` |
| Keycloak realm 設定 | 管理介面匯出（可讀的參考副本；還原以資料庫為準） | `keycloak-realm.json` |
| 筆數清單 | 每張表的列數、物件數、Orthanc 病人／研究／序列／影像數、Keycloak 帳號數 | `manifest.txt` |
| 完整性 | 所有檔案的 SHA-256 | `SHA256SUMS` |

不備份：MinIO 的磁碟檔（改用匯出）、病毒碼（可重新下載）、模擬 PACS（不是平台資料）。volume 清單由 compose 專案的標籤探索，其他工作包新增的 volume 會自動納入；要排除的以 `SKIP_VOLUMES_RE` 設定。

## 指令

```bash
cd platform/compliance
COMPOSE_PROJECT=ai-platform scripts/backup.sh /備份/位置/20260929     # 備份
COMPOSE_PROJECT=ai-platform scripts/restore.sh /備份/位置/20260929    # 還原（會覆蓋目標環境）
```

還原順序：檢查 SHA-256 → 停下 API 與 Keycloak → 還原角色與資料庫 → 還原 volume（先停下使用它的服務）→ 啟動 Keycloak 與 API → 寫回物件。

## 還原演練（TC-D02-02）

```bash
COMPOSE_PROJECT=ai-wp8 KEYCLOAK_HOST_PORT=18380 GATEWAY_HOST_PORT=19380 PACS_HTTP_PORT=18343 \
  CONFIRM_DESTROY=ai-wp8 scripts/restore-drill.sh
```

演練流程：備份 → `docker compose down -v` 刪除所有資料 → 以空資料重新啟動 → 還原 → 重新產生筆數清單並與備份時比對，差異 0 才通過。
2026-09-29 在開發機演練一次：比對 110 項（含 PostgreSQL 各表、物件 18 個、Orthanc 影像 100 張、Keycloak 帳號 10 個），差異 0，全程約 65 秒。

## 正式環境的差異（甲方環境驗證）

- 備份要寫到與平台不同的儲存（異地或離線媒體），並依甲方政策保留份數。
- 正式環境的 PostgreSQL、物件儲存、Orthanc 在 Kubernetes 內，指令改成 `kubectl exec`；步驟與比對方式相同。
- 還原演練要在甲方環境再做一次（TC-D02-02 地點為「Mac／甲方」）。
