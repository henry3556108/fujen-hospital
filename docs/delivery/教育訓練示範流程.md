# 教育訓練示範流程（D-02）

示範以無程式碼的網頁操作為主。每一段都有對應的 Playwright 腳本（`platform/web/e2e/demo-flow.spec.ts`），確保教材寫的步驟實際做得到（TC-D02-03：示範無法重現 0）。

| 段落 | 內容 | 狀態 |
|---|---|---|
| 1 | Admin 建立專案、指派成員與角色；成員登入後只看到有權限的入口 | 可示範，腳本通過（Chromium、Edge） |
| 2 | 上傳影像與 CSV、篩選、檢視統計 | 可示範，腳本通過（Chromium、Edge） |
| 3 | 影像標註、自動標註、修改後儲存 | 可示範，腳本通過（Chromium、Edge） |
| 4 | 建立訓練、匯出模型、部署與推論 | 可示範，腳本通過（Chromium、Edge）：從資料集「用這份資料建立訓練」、K 折交叉驗證、看結果圖表與報表、「部署此模型」與試用預測，在「推論服務管理」推論 |
| 5 | FHIR 資料來源、對應規則、排程 | 可示範，腳本通過（Chromium、Edge） |
| 6 | LLM Playground、知識庫、發布 API | 可示範，腳本通過（Chromium、Edge） |

各段落從首頁開始、只點頁面上的連結與按鈕，彼此不依賴。

## 段落 2：上傳影像與 CSV、篩選、檢視統計

以 Research Assistant 登入。

1. 「數據管理」→ 選「醫療影像」：「匯入影像」上傳 DICOM，按「到研究列表查看」，以 Study Description 等條件篩選。
2. 上方分頁切到「結構式資料（CSV 表格）」（或在「數據管理」首頁直接選「結構式資料：上傳 CSV」）。
3. 選擇 CSV 檔。平台自動判斷每一欄的型態，列在「欄位確認」表：整數、小數、類別、文字、日期、是否。每欄旁邊有缺值數、不同值數、範例與提示。
4. 依提示檢查：例如某欄「有 2 格空白」而這欄不該空白，就勾選「必填」；年齡、血壓等常見欄位已自動帶入合理範圍，可自行修改。按「重新預檢」看會有幾列被拒絕、原因是什麼。
5. 填資料集名稱，按「上傳並驗證」。不符合的列被拒絕並逐列列出原因，其餘的列進入資料集。名稱重複時可選「建立新版本」或「取代舊的」。
6. 按「開啟資料集」：「描述統計」看各欄的平均、中位數與分布（0／1 欄位顯示為是／否與比例）；「相關與散佈圖」產生相關矩陣。
7. 「Target／Feature」：在欄位總覽表選 Target（要預測的欄位，例如 diagnosis）與 Feature（用來預測的欄位）。表上會提示缺值多、像病歷號的識別碼、只有一種值的欄位。文字欄位（例如 sex）按「全部轉成 One-Hot」；以數字代表分類的欄位（例如 0、1、2）打開「當作類別」。按「儲存設定」，Feature 會自動換成 One-Hot 產生的欄位。

已經有結構定義檔（JSON）的進階使用者，可在上傳表單的「進階：自行提供結構定義（JSON）」載入；檔案中有、結構定義沒列出的欄位，上傳前會詢問要自動加入或捨棄。

### 資料準備須知

平台能自動處理的不需要事先整理：欄名可以用中文、空白與符號；空白、`NA`、`N/A`、`-` 等自動視為缺值；Excel 另存的 CSV（UTF-8 或 Big5）都可以；不必把文字改成數字代碼。只需要注意：

1. 一列一位病人（或一次就診），第一列是欄名，欄名不可空白或重複。
2. 同一欄只放一種內容，單位一致（例如體重都用公斤）；日期寫成 `2024-01-31`。
3. 移除姓名、身分證字號等可直接識別個人的欄位；病歷號可保留，但不要當 Feature。
4. 要預測的結果（Target）放在同一欄，例如是否診斷為 0／1。

## 段落 4：建立訓練、匯出模型、部署與推論

以 Principal Investigator（有 Training 與 Coding 權限）登入。

1. 「數據管理」→「結構式資料」→ 點資料集名稱（例如 `lung-clinical`）→ 按「用這份資料建立訓練」。「建模管理」會開好新增表單：已選好資料集，帶入資料集設定過的 Target、Feature 與前處理，並依目標欄位預選「結構式分類」（類別或 0／1）或「結構式迴歸」（連續數字）。
2. 確認或選擇目標欄位（Target）與特徵欄位（Feature）。文字或類別欄位（例如性別、吸菸）不用先處理，訓練時會自動轉成 0／1 欄位。
3. 驗證方式：資料幾百筆時選「K 折交叉驗證」（K 用 5）；資料很多時用「固定比例切分」。每個超參數旁都有白話說明與建議值，不確定就保留預設值；不常調的收在「進階設定」。亂數種子決定資料怎麼隨機分組，同一個號碼重跑結果完全相同，一般不用改。按「儲存設定」。
4. 在訓練設定清單按「送出訓練」。送出前平台會先檢查設定與資料是否一致（例如資料集的 Target／Feature 改過、勾了病歷號這類每列都不同的欄位），有問題會直接說明，不會排隊後才失敗。資料集設定改過時，訓練設定旁會出現「資料集設定已更新」，按「套用資料集設定」即可。
5. 「訓練紀錄」的步驟條會自動更新：已送出 → 排隊中 → 訓練中 → 完成（或失敗）。失敗時只顯示中文原因與「前往修正」連結，程式訊息收在「技術細節」。
6. 完成後看「模型好不好？」：每個指標都有一句白話（例如「準確率 65%：測試集的 20 人中猜對 13 人」）與怎麼看才算好；和「全部都猜最常見類別」的比較基準對照；二元分類另有 AUC、敏感度、特異度。測試人數少、驗證與測試差很多時會有提醒。K 折會列出平均±標準差。圖表有混淆矩陣、ROC 曲線、特徵重要性（迴歸為預測值對實際值與殘差分布）。按「下載報表（可列印）」得到一頁 HTML，可用瀏覽器列印成 PDF。訓練清單可按「主要分數」排序，預設只列自己送出的。
7. 「模型匯出」：「下載模型（PKL）」（影像為 H5），畫面顯示檔名與 SHA-256；「匯出原始碼」下載範本＋這次設定的 zip（需要 Coding 權限）。
8. 按「部署此模型」：「AI 模型部署」頁已選好這個模型並建議部署名稱，填授權帳號後按「部署」。線上部署清單顯示呼叫端點 `POST /api/inference/<部署名稱>/predict` 與呼叫範例；可「管理授權」修改帳號、「取消部署」停止端點。
9. 「試用預測」：填一位病人的資料，按「預測」看預測類別與機率。
10. 「推論服務管理」：選模型，上傳影像或 CSV 推論，檢視結果與歷史、下載結果。結構式分類的結果多一欄「預測類別的機率」。

影像訓練（影像分類、分割、物件偵測）在「建模管理」按「新增訓練設定」，選訓練種類、標註來源、Label、Resize 與資料增強。「建模管理」下方的「專案工作」可查看訓練在 GPU 佇列的排隊與執行狀態。

```bash
cd platform/web
npx playwright test e2e/demo-flow.spec.ts      # 測試模式（模擬 API），Chromium 與 Edge
```
