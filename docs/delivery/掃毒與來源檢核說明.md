# 掃毒與來源檢核說明（D-01）

## 上傳掃毒（TC-D01-06）

- **上傳當下掃**：平台 API 在寫入前把檔案送到 ClamAV（clamd 的 INSTREAM 協定）。結構式資料上傳被攔下時回 422，影像批次上傳時該檔記為失敗、同批其他檔不受影響。每次攔截寫一筆「資料集」類稽核（動作 `malware_blocked`，含病毒特徵名稱）。
- **所有物件儲存寫入都會掃**：物件儲存外包了一層掃毒，其他工作包新增的上傳功能不用另外接。DICOM 走 Orthanc，不經物件儲存，另在影像匯入時掃描。
- **掃毒服務中斷時拒絕上傳**（fail closed），回 503 並說明原因。
- **設定**：`CLAMAV_HOST`、`CLAMAV_PORT`（預設 3310）。未設定時不掃描，API 啟動時記一行警告；開發機以 `platform/deploy/local/compose.compliance.yaml` 疊加檔啟用。
- **定期掃**：`python -m compliance malware --compose-project <專案>` 掃描物件儲存（經 API 匯出）與專案的檔案型 volume。每次都放一個 EICAR 測試檔一起掃，沒攔下就算失敗，避免「掃毒其實沒在運作」卻回報乾淨。病毒碼更新後，這也能抓到上傳當時還沒有特徵的檔案。
- EICAR 測試字串只在測試執行時組出來，不存進版本庫。

## 映像來源與非專案軟體（TC-D01-07）

- 核准的映像來源寫在 `platform/compliance/policy/image-sources.yaml`，每一條附理由。新增映像時若來源不在清單內，`python -m compliance sources` 會失敗，需負責人審核後加入。
- 沒有釘版本（`latest` 之類）的映像列為警告：之後拉到的內容可能和授權清單不同。目前只有 `cgr.dev/chainguard/minio:latest`（Chainguard 免費映像只提供 latest），建議正式環境改用 digest 釘住。
- `--running` 另比對執行中的容器與叢集 Pod：用到的映像都必須是探索到的映像、平台自建映像或節點內建元件，否則列為「非專案軟體」。

## 漏洞掃描（TC-D01-07）

- `python -m compliance vulns` 以 Trivy 掃描所有探索到的映像與平台自建映像，報告寫到 `platform/compliance/out/vulnerabilities.md`（不進版本庫）。
- 預設只回報不擋下；`--fail-on HIGH` 可設定門檻。門檻與修補期限需與甲方議定。

## 授權清單（TC-D01-01）

- `python -m compliance licences generate` 產生 `docs/delivery/第三方授權清單.md` 與 `docs/delivery/licence-list/`；`check` 重新掃描並比對，任何差異（多、少、版本、授權、digest）都算失敗。
- 範圍：容器映像（含作業系統套件）、平台自建映像、各子專案的 Python 與 Node 套件。
- 不在範圍：主機作業系統、GPU 驅動、CUDA（甲方環境建置時補）；AI 模型與 LLM 權重（由 WP7 的模型白名單審核紀錄提供，合併後併入）。
- 很多 Go 與作業系統元件在映像內沒有授權中繼資料，清單標為「未標示」。這是掃描工具能取得的極限，要逐項補齊需人工查核上游專案。

## 映像內 Python 套件（TC-A01-04）

- `python -m compliance packages generate` 產生 `docs/delivery/python-packages/<映像>.txt`；`check` 比對實際映像。
- 產生後的清單要經負責人確認後 commit，之後的 `check` 就是和「已確認清單」比對。
