# 正式環境升級說明（2026-11-10 版）

把甲方正式環境（Kubernetes，命名空間 `ai-platform`）升級到分支 `ui/redesign` 的 commit `f6166d1`（含之後只改文件的 commit）。
第一次安裝請看 `部署說明.md`；本文只寫「已經在跑的環境要換成這一版」要做的事。

## 這一版改了什麼

| 類別 | 內容 |
|---|---|
| 介面 | 照設計稿重做外框與五區頁面、研究區與管理區重排、標註資料集與狀態、資料範圍、專案首頁；全站用語統一（各階段處理程式碼、描述性統計、One Hot Encoding、前處理步驟） |
| 標註／訓練 | 標註狀態（待確認／已確認）、標註資料集版本、訓練可選資料集版本與測試集；影像分類訓練多了指標（訓練映像要換） |
| LLM（八、6／八、8） | ① 平台預設的對話模型、嵌入模型，以及內部服務或知識庫正在使用的模型，不能卸載或刪除；卸載只限下載者或管理者（修正「一個專案卸載 gemma，全平台對話 503」）② PDF 的康熙部首字元還原成一般字 ③ RAG 指示文字改寫 ④ 內部服務頁加上取得 Token 與呼叫 API 的步驟 ⑤ 模型清單只列模型服務實際有的模型 |

**不變的部分**：Keycloak realm、Secret、NetworkPolicy、Ingress、上游映像（PostgreSQL、Keycloak、Ollama…）、自動標註映像都沒改，不需要動。

## 會換的映像

| 映像 | 原因 |
|---|---|
| `platform-api` | 後端程式 |
| `platform-web` | 網頁 |
| `platform-trainer`、`platform-trainer-gpu` | 訓練範本（影像分類指標） |

平台映像在 `components/images/kustomization.yaml` 的 tag 是 `dev`，Pod 的 `imagePullPolicy` 是 `IfNotPresent`：
**如果沿用 `dev`，節點已經有舊的 `dev` 就不會重拉，等於沒升級**。這次請用新的 tag，下面以 `20261110` 為例。

## 資料庫

會新增資料表 `imaging_scopes`、`label_datasets`、`label_dataset_versions`，以及欄位：

- `label_annotations.status`（舊資料預設 `confirmed`）、`confirmed_by`、`confirmed_at`
- `training_runs.label_dataset_id`、`label_dataset_version`、`test_count`

都由部署時自動執行的 db-init 建立（只新增、不刪不改既有資料），**不需要手動跑 SQL**。新欄位都允許空值或有預設值，退回舊版時舊程式不會讀到它們，不影響運作。

## 部署後驗證（約 10 分鐘）

| # | 驗證 | 怎麼做 | 預期 |
|---|---|---|---|
| V1 | 網頁 | 瀏覽器開 `https://<平台網域>/`，強制重新整理（Ctrl+F5）後以 admin01 登入 | 新版版面；LLM 各分頁標題是「LLM No-code 開發」 |
| V2 | 未登入被擋 | 不帶 token `GET https://<平台網域>/api/admin/projects` | 401 |
| V3 | 八、6 RAG | 用 PI 帳號在一個專案建 RAG 知識庫，上傳一份 PDF → Chat with Knowledge Base 問文件裡的事 | 回答正確並列出出處 |
| V4 | 預設模型受保護（Frank 回報的 8-6） | PI 在模型管理對 gemma 按「卸載」；Admin 再按一次 | PI：「只有下載這個模型的人或管理者可以卸載」；Admin：「…是平台預設的對話模型…不能卸載」。之後 V3 的對話仍正常 |
| V5 | 八、8 Token（Frank 回報的 8-8） | PI 把知識庫發布成內部服務並授權給一個 MD 帳號 → 照「內部服務」頁「RESTful API 呼叫方式」的步驟：申請登入碼 → 瀏覽器以 MD 帳號登入 → 換 Token → `curl` 呼叫 | 呼叫回 200 與答案；未授權的帳號 403 |
| V6 | 訓練 | 跑一個既有的小型訓練設定 | 成功；結果頁有指標 |

V3～V5 用的測試專案、服務驗證完可以刪除（管理區 → 專案 → 刪除）。

## 出問題時退回

```bash
helm history ai-platform -n ai-platform               # 找步驟 0 記下的 REVISION
helm rollback ai-platform <REVISION> -n ai-platform   # manifest（含映像 tag）回到舊版
```

- 退回只回復 manifest，資料庫多出來的表與欄位留著，舊版程式不會用到，不必刪。
- 舊映像仍在 registry（舊 tag），rollback 後 Pod 會用回舊映像。
- 若必須連資料一起回到升級前，照 `備份與還原說明.md` 用步驟 1 的備份還原，再執行一次 `./deploy.sh production`。
