# 新增功能的使用情境（2026-10-12）

這一輪新增的功能，依使用者會遇到的情境整理。每個情境寫出角色、情境、逐步操作與要注意的地方。
步驟中「」內是畫面上實際的文字；括號內是對應的模組。左側選單只會顯示目前專案中有權限的入口（畫面上方「目前專案」切換專案）。

| 功能 | 情境 |
|---|---|
| 佇列順序、暫存與恢復排隊、另存為訓練設定 | A1–A4 |
| LLM 真模型：Hugging Face 下載、量化載入、執行狀態 | B1–B4 |
| 知識庫（RAG）與 Prompt 範本搭配真模型 | B5–B7 |
| 真實自動標註工具 MONAI Label | C1–C2 |
| GPU 共享池扣除常駐服務的份數 | D1 |
| 功能缺口補齊：刪除專案停線上服務、批次推論狀態、選帳號、部署試呼叫、訓練紀錄分頁 | E1–E5 |

## A. 排程：佇列順序與暫存

### 情境 A1：緊急工作插隊

**角色**：Admin

GPU 佇列裡排了好幾個訓練，其中一個是明天要給院長看的模型，需要先跑。

**操作步驟**

1. 左側選單點「帳號管理」，上方分頁點「共享排程設定」，再點分頁「佇列順序」（C-01）
2. 頁面依佇列分成三張卡片：「GPU 獨占池（gpu-exclusive）」「GPU 共享池（gpu-shared）」「CPU 資料處理（cpu-data）」。找到要調整的佇列
3. 表格的「順序」欄：執行中的工作顯示「執行中」或「即將開始」，操作欄是「不可移動」；等待中的工作顯示「第 N 位」
4. 在要先跑的工作那一列按「↑」，直到它變成等待中的「第 1 位」；畫面出現「順序已調整，尚未套用。」
5. 按該卡片的「套用順序」，出現「已套用 gpu-exclusive 的順序：…」即完成
6. 想放棄這次調整，在套用前按「還原」

**要注意**

- 套用的瞬間如果剛好有工作被放行，會出現「資料衝突：佇列 … 目前等待中的工作是 …，與送出的清單不同…」；按「重新整理」後再調一次
- 調整順序寫在「專案」類稽核

### 情境 A2：先把自己排隊中的訓練收起來，晚點再跑

**角色**：有 Training 權限的研究員（工作的建立者）

研究員送出訓練後發現資料集還要補幾筆，不想讓它先占用 GPU，也不想取消後重填一次設定。

**操作步驟（從訓練紀錄）**

1. 左側選單點「建模管理」，往下到「訓練紀錄」（B-05）
2. 找到狀態為「排隊中」的訓練，按「展開訓練 #N」
3. 按「暫存」；狀態變成「已暫存」，說明為「已暫存：移出佇列，按「恢復排隊」後重新排到最後」
4. 資料補好後，回到同一筆訓練按「恢復排隊」，狀態回到「排隊中」，排在佇列最後

**操作步驟（從專案工作頁）**

1. 「建模管理」頁的「排程」區塊點「專案工作」
2. 「工作列表」中找到狀態「排隊中」的工作，按「暫存」；出現「已暫存工作 N，之後按「恢復排隊」會排到佇列最後」
3. 要恢復時按同一列的「恢復排隊」；出現「工作 N 已恢復排隊（排在佇列最後）」

**要注意**

- 只有排隊中的工作可以暫存；已開始訓練的按暫存會出現「訓練 N 已開始訓練，無法暫存（訓練中無法中途保存進度，只能取消）」
- 恢復時仍用暫存當時凍結的資料

### 情境 A3：維護前先清空佇列

**角色**：Admin

週末要更新 GPU 主機的驅動，Admin 不想讓等待中的工作在維護途中被放行。

**操作步驟**

1. 「帳號管理 → 共享排程設定 → 佇列順序」（C-01）
2. 在每張佇列卡片中，對每一列「第 N 位」的工作按「暫存」；出現「已暫存工作 N」，該列的順序欄變成「暫存（暫存者，時間）」
3. 等表格中的「執行中」工作全部結束（可按「重新整理」確認），進行維護
4. 維護完成，依原本的先後對各列按「恢復排隊」；出現「工作 N 已恢復排隊（排在佇列最後）」

**要注意**

- Admin 在這頁可以暫存與恢復任何人的工作；一般使用者只能處理自己的（A2）
- 依原本先後逐一恢復，就能維持原來的順序

### 情境 A4：用上次的訓練設定再跑一次

**角色**：有 Training 權限的研究員

上個月訓練出一個不錯的模型，現在資料多了，想用同一套參數重新訓練。

**操作步驟**

1. 「建模管理 → 訓練紀錄」，必要時取消勾選「只看我送出的」或翻頁找到那次訓練（B-05）
2. 按「展開訓練 #N」，再按「另存為訓練設定」
3. 「新設定名稱」預設為「原名稱（訓練 #N）」，可修改；按「儲存設定」
4. 出現「已另存為訓練設定「…」，之後可在上方的訓練設定隨時送出訓練（會重新凍結當時的資料）。」
5. 回到頁面上方的訓練設定清單，在新設定那一列按「送出訓練」

**要注意**

- 送出時會依當下的資料重新凍結，不會沿用當時的資料快照；要完全重現同一次訓練，改按「以同一資料版本與種子重跑」

## B. LLM：真模型與知識庫

LLM 的畫面在左側選單「LLM No-code 開發」，需要目前專案的 **Coding** 權限；分頁有「Playground／模型管理／Prompt 範本／知識庫／發布 API／工作流／Wiki」。
模型白名單由 **Admin** 管理，下載前也要 Admin 核准。

### 情境 B1：從 Hugging Face 引進一個新模型

**角色**：Admin（登記白名單、核准）、有 Coding 權限的研究員（申請、下載、載入）

研究團隊想試用另一個開源模型。醫院規定只能用審核過、版本固定的模型。

**操作步驟**

1. Admin 登記白名單（目前沒有網頁表單，由維運人員代為執行）：
   - 在 `platform/deploy/local/llm/models.json`（正式環境為 `deploy/k8s/overlays/production/config/llm-models.json`）加一筆，填名稱、`repo`、`revision`（commit）、`files`（只允許下載的檔案，例如 `*Q4_K_M.gguf`）、授權
   - `sha256` 以 Admin 帳號呼叫 `POST /api/admin/llm/whitelist/inspect`（帶 repo 與 commit）取得後填入
   - 執行 `docker compose exec -T api /app/.venv/bin/python -m app.llm.model_setup /opt/llm-models.json`；或用同一個 inspect 結果直接呼叫 `POST /api/admin/llm/whitelist`
2. 研究員進入「LLM No-code 開發 → 模型管理」，在「可下載模型（白名單）」找到新模型（狀態「未下載」），按「申請下載」（B-07）
3. Admin 進入同一頁，「待審核的下載申請」會列出「模型名稱（申請人 帳號）」，按「核准」（不同意按「駁回」）
4. 研究員回到「模型管理」，模型狀態變成「已核准，待下載」，按「下載」
   - 需要授權的模型，先在上方「下載 Token（需要時填寫，不會被儲存）」填入 Hugging Face Token 再按「下載」
5. 狀態顯示「下載中 NN%（X MB / Y MB）」，每 3 秒更新；完成後變成「已下載」
6. 「下載紀錄」中可看到這次下載的申請人、審核人、commit 與 hash
7. 往下到「模型名稱 載入與資源」，按「載入」；狀態變成「已載入」

**要注意**

- 下載完成時平台會核對 commit 與 hash，不符就標為「失敗」，不會載入
- 每一步都寫入稽核；Token 不儲存，稽核只記指紋
- 正式環境要能連外到 `huggingface.co` 與 `cas-bridge.xethub.hf.co`

### 情境 B2：醫院沒有對外網路時引進模型

**角色**：維運人員、Admin、有 Coding 權限的研究員

甲方的正式環境不能連外，但仍要用同一個經審核的模型。

**操作步驟**

1. 在可上網的機器，從 Hugging Face 下載白名單登記的同一個 commit 的模型檔
2. 依下列結構整理，帶進院內放到離線預載目錄（compose 掛在 api 的 `/opt/llm-preload`，主機目錄由 `LLM_PRELOAD_HOST_DIR` 指定）：
   ```
   模型名稱/
     manifest.json     {"repo": "…", "commit": "…"}
     模型檔.gguf
   ```
3. 照 B1 的第 2–7 步申請、核准、按「下載」；平台連不上 Hugging Face 時改從預載目錄取，一樣核對 commit 與 hash
4. 「下載紀錄」的狀態會顯示「完成（離線預載）」

### 情境 B3：調整模型的量化與資源

**角色**：有 Coding 權限的研究員

4-bit 模型的回答品質不夠好，想改用 8-bit 試試；或想確認模型實際跑在 GPU 還是 CPU。

**操作步驟**

1. 「LLM No-code 開發 → 模型管理」，往下到「模型名稱 載入與資源」（B-07）
2. 修改欄位：
   - 「量化」：不量化／4-bit／8-bit
   - 「CPU」：CPU 執行緒數
   - 「記憶體（GB）」
   - 「GPU 類型」：獨占 GPU／共享 GPU／只用 CPU
   - 「GPU 張數」
3. 模型已載入時按「套用並重新載入」，出現「已依新設定重新載入」；模型未載入時按「儲存載入設定」，之後再按「載入」
4. 下方顯示模型服務回報的執行狀態，例如「模型服務回報：量化 Q8_0、CPU 執行緒 4、在 GPU 上執行、顯示記憶體 4800 MB」
5. 不用時按「卸載」釋放 GPU 記憶體，出現「已卸載」

**要注意**

- 預設模型：Gemma 3 4B（對話，提供 4-bit 與 8-bit）、EmbeddingGemma 300M（知識庫向量）
- 「Playground → 生成參數」中的 Length Penalty 在真模型上只儲存、不生效（Ollama 沒有對應參數）；其他 5 個參數與 System Prompt 都會實際送到模型

### 情境 B4：新環境一次裝好預設模型

**角色**：維運人員

在新的主機部署平台後，要讓 LLM 功能立即可用。

**操作步驟**

1. 確認 api 能連到 `huggingface.co` 與 `cas-bridge.xethub.hf.co`；不能連外時先依 B2 放好預載目錄
2. compose 環境執行：
   ```
   docker compose exec -T api /app/.venv/bin/python -m app.llm.model_setup /opt/llm-models.json
   ```
   Kubernetes 正式環境在 api 的 Pod 內執行同一個指令（見 `platform/deploy/k8s/README.md`「正式環境」）
3. 指令依序登記白名單、申請、核准、下載並核對、依 `models.json` 的 `load` 設定載入；每一步印出結果
4. 登入網頁「LLM No-code 開發 → 模型管理」，確認兩個模型都顯示「已載入」

**要注意**

- 可重複執行，已完成的步驟會略過；中途失敗修正後重跑即可
- 每一步以 `system-setup` 身分寫進稽核

### 情境 B5：用院內文件建知識問答

**角色**：有 Coding 權限的研究員

護理部想讓同仁用自然語言查詢院內的作業規範，例如「自助報到機故障怎麼處理」。

**操作步驟**

1. 「LLM No-code 開發 → 知識庫」，在「知識庫名稱」輸入名稱，按「新增知識庫」（B-07）
2. 新知識庫會自動選取，出現「文件（知識庫名稱）」區塊
3. 在「選擇檔案（PDF、DOCX、TXT、CSV、JSON、HTML，可多選）」按「選擇檔案」，選好文件後按「上傳並建立向量」
4. 出現「寫入 N 份、重複 N 份、失敗 N 份」，以及每個檔案的結果（已寫入／重複／失敗與原因）；文件清單顯示「檔名（PDF，N 個片段）」
5. 切到「Playground」分頁，「對話模式」選「Chat with Knowledge Base」，「知識庫」選剛建立的知識庫
6. 在「訊息」輸入問題，按「送出」（或 Enter）
7. 回應下方顯示「出處：檔名…」與「回應時間 N 秒」

**要注意**

- 文件以 EmbeddingGemma 向量化；中文文件測試 10 題全部找對
- 同一份文件重複上傳會判為重複，不重複寫入
- 目前只能刪除整個知識庫（列表中的「刪除」，沒有確認視窗），不能刪除單一文件

### 情境 B6：Prompt 範本與知識庫一起用

**角色**：有 Coding 權限的研究員

研究員有一個「用病人聽得懂的話解釋」的範本，想讓它搭配衛教知識庫回答。

**操作步驟**

1. 「LLM No-code 開發 → Prompt 範本」，在「新增 Prompt」填（B-07）：
   - 「標題（必填）」
   - 「tag（以逗號分隔）」
   - 「可見範圍」：個人（只有自己看得到）或公開（專案成員都看得到）
   - 「內容（必填，可用 {input} 代表使用者輸入）」，例如「請用病人聽得懂的話回答：{input}」
2. 按「新增 Prompt」，出現「已新增 Prompt「…」」
3. 切到「Playground」：
   - 只用範本：「對話模式」選「Free Chat」，「Prompt 範本」選剛建立的範本
   - 只用知識庫：「對話模式」選「Chat with Knowledge Base」並選知識庫，「Prompt 範本」選「不使用」
   - 兩者一起：選知識庫，也選範本
4. 輸入訊息按「送出」；用到知識庫時回應下方會列出「出處」
5. 要比較不同組合時按「開新對話」清空對話

### 情境 B7：把知識問答發布給其他系統呼叫

**角色**：有 Coding 權限的研究員

B5 的知識問答測試滿意後，要提供給護理部的系統呼叫。

**操作步驟**

1. 先在「Playground → 生成參數」調整並按「儲存生成參數」；發布時會使用目前的生成參數
2. 「LLM No-code 開發 → 發布 API」，在「發布為內部 API」填（B-07）：
   - 「服務代號（小寫英數字與 -）」
   - 「名稱」
   - 「知識庫」：選 B5 的知識庫
   - 「授權帳號（以逗號分隔）」：輸入帳號開頭，點選下方列出的帳號（見 E3）
3. 按「發布」，出現「已發布「名稱」：POST 端點」；列表的「端點」欄也會顯示呼叫位址
4. 暫停服務按「停用」，恢復按「啟用」；不再提供按「取消發布」

**要注意**

- 只有「授權帳號」內的帳號能經 Gateway 呼叫
- 發布表單不能選 Prompt 範本

## C. 影像：真實自動標註

### 情境 C1：用 MONAI Label 自動標出器官再由醫師修正

**角色**：有 Labeling 權限的醫師

醫師要標註一批腹部 CT 的脾臟，手動逐張描邊太慢。

**操作步驟**

1. 左側選單點「自動影像分類標註」（B-03）
2. 在「送出自動標註」選：
   - 「模型」：只標脾臟選「segmentation_spleen（分割：spleen）」；要 25 種器官選「segmentation（分割：spleen、kidney_right…）」
   - 「研究」：依 Accession、日期、描述選擇研究
   - 「影像」：「第 N 張」
3. 按「送出自動標註」，按鈕顯示「標註中…」
4. 完成後出現「自動標註完成：已存為分割標註 #N（耗時 X 毫秒）。」，點「在標註工作台開啟編輯」
5. 進入「影像標註工作台」，畫面提示「正在編輯標註 #N」；用筆刷修正遮罩
6. 按「儲存分割標註」（或 Ctrl+S），出現「已儲存分割標註 #N（…，版本 V）」
7. 之後要找回這筆結果，在「自動影像分類標註」頁下方的「執行紀錄」點「開啟編輯」

**要注意**

- 第一次推論（含取像與載入模型）約 4 秒；同一序列的其他張直接取快取，0.05 秒內
- 頁面使用研究中的第一個序列；結果依規格 1.0 為 2D 單張，MONAI 實際以 3D 整個序列推論
- 與公開資料集的標準答案比對，Dice 0.981
- 是否算合約的「Clara 等級或同等」，仍待甲方書面確認

### 情境 C2：切換自動標註工具

**角色**：維運人員

驗收或展示時要用真實的 MONAI Label；沒有 GPU 的測試機改用假服務。

**操作步驟（開發或展示環境）**

1. 第一次使用先建映像（WSL2 上用主機網路，下載快很多）：
   ```
   BUILD_NETWORK=host platform/autolabel/build.sh
   ```
2. 在 `platform/deploy/local` 啟動時加上 MONAI 疊加檔：
   ```
   docker compose -f compose.yaml -f compose.labeling.yaml -f compose.monai.yaml up -d --no-build --wait
   ```
3. 登入網頁「自動影像分類標註」，「模型」選單出現脾臟與 25 種器官模型，代表已切換
4. 要換回假服務：拿掉 `-f compose.monai.yaml` 再執行一次 `up -d`

**操作步驟（正式環境）**

1. production overlay 已設定 MONAI Label（`autolabel-monai.yaml`），部署後即生效
2. 改接甲方指定的其他工具時，把 kustomization 的 `AUTOLABEL_URL` 改成該工具的位址後重新部署

**要注意**

- MONAI Label 透過 Orthanc 唯讀帳號取像，只能讀 DICOMweb，不能刪改影像
- 沒有 GPU 時推論要數十秒，平台會先回「稍後再試」；背景算完後再送一次就會成功

## D. 維運

### 情境 D1：GPU 共享池同時跑常駐服務與訓練

**角色**：Admin、維運人員

正式環境中，Ollama（LLM）與 MONAI Label 各常駐占用 GPU 共享池的一份時間片，不經佇列排程。

**操作步驟**

1. 維運人員確認 production overlay 的 `GPU_SHARED_RESERVED`：預設 2（Ollama、MONAI Label 各一）；常駐服務增減時改這個數字並重新部署
2. Admin 進入「帳號管理 → 共享排程設定」，「目前設定」顯示「時間片份數」與「工作時限（分鐘）」
3. 在「修改設定」填「時間片份數（1–16）」與「工作時限（分鐘，1–1440）」，按「儲存設定」
4. 出現「已儲存：時間片 N 份、工作時限 M 分鐘」；平台同步佇列配額時，自動扣掉常駐服務的份數

**要注意**

- 例：共享 GPU 1 張、時間片 4 份、常駐 2 份 → 佇列最多同時放行 2 件共享池工作
- 不扣的話，佇列會放行超過實際可用份數的工作，工作被放行後卻排不上節點

## E. 功能缺口補齊

### 情境 E1：研究結案，刪除專案時線上服務一併停止

**角色**：Admin

研究結案後 Admin 刪除專案，專案部署給外部系統呼叫的線上推論服務也必須跟著停止，避免結案後仍有人能用這個模型。

**操作步驟**

1. 左側選單點「帳號管理」，分頁點「專案」（A-03）
2. 在要刪除的專案那一列按「刪除」
3. 確認視窗顯示「確定要刪除專案「…」嗎？專案成員資格會一併移除，此動作無法復原。」，按「確認刪除」
4. 出現「已刪除專案「…」」
5. 原本經 Gateway 呼叫這個專案部署的系統，之後一律得到 403

**要注意**

- 平台同時從推論服務卸載這個專案的所有模型，釋放記憶體；卸載失敗（例如推論服務暫時離線）會記下來，之後自動重試
- 稽核在「專案資料清理」一筆中記錄卸載的模型數，不逐一記每個部署

### 情境 E2：批次推論跑完，工作狀態即時更新

**角色**：有 Prediction 權限的研究員；查看工作頁需要 Training 權限

研究員送出整份測試資料的批次預測，想知道什麼時候跑完；同時在工作頁確認 GPU 工作已結束。

**操作步驟**

1. 左側選單點「推論服務管理」，在「模型」表格按「選擇 模型名稱」（B-06）
2. 在「多位病人一起預測」（影像模型為「多張影像一起預測」）的「資料範圍」選「測試資料」，按同名按鈕送出
3. 畫面顯示「批次預測排隊中…在背景執行，完成後自動顯示結果；離開此頁也不影響…」
4. 完成後自動出現「預測結果 #N（K 筆）」，可按「下載結果」；「預測紀錄」的「結果」欄為「成功」或「失敗：原因」
5. 到「建模管理 → 專案工作」，這件工作的「種類」顯示「批次推論（GPU）」或「批次推論（CPU）」，「狀態」已是「已完成」或「失敗」，不必等任何人重新整理

**要注意**

- 工作狀態依推論程式的回報；若回報成功但結果格式不合格，工作顯示「已完成」，預測紀錄顯示「失敗」與原因

### 情境 E3：分享模型給同事時直接挑帳號

**角色**：有 Training 權限的研究員（不是 Admin）

研究員要把訓練好的模型分享給另一位醫師，但不記得對方的帳號怎麼拼；以前只有 Admin 能列出帳號，只能去問。

**操作步驟**

1. 左側選單點「AI 模型部署」，到「分享給同事使用」（B-06）
2. 「模型」選要分享的模型，「顯示名稱（同事看到的名稱，可用中文）」填名稱
3. 在「分享給（同事的帳號，以逗號分隔）」輸入帳號開頭，例如「md」
4. 下方列出符合的帳號按鈕；本專案成員排在前面，非成員顯示「帳號（不是本專案成員）」。點一下即加入欄位，可再輸入下一個
5. 按「分享給同事使用」，出現「已把「…」分享給 …。他們登入後點左側「推論服務管理」，選模型「…」就能預測。」
6. 之後要增減對象，在「已分享的模型」該列按「修改分享對象「…」」，同樣輸入開頭點選，按「儲存分享對象」

**要注意**

- 查詢只回傳帳號與是否為本專案成員，不顯示 email 等其他資料；一次最多 20 筆
- 需要該專案的 Training 或 Coding 權限才能查詢；「LLM No-code 開發 → 發布 API」的「授權帳號」欄位也可以這樣選
- 分享給非成員時會提醒：對方在「推論服務管理」看不到這個模型，但可以用程式呼叫

### 情境 E4：分享後先在網頁上試呼叫

**角色**：有 Training 權限的研究員

研究員分享模型後，想在交給資訊室串接之前，先確認服務真的能用、回應長什麼樣子。

**操作步驟**

1. 「AI 模型部署 → 已分享的模型」，表格的「模型」欄顯示每個分享實際用的是哪個模型（B-06）
2. 先確認自己在「分享給」欄位中；不在的話按「修改分享對象「…」」把自己加入
3. 在「試呼叫」的「要呼叫的分享」選擇要測試的分享
4. 結構式模型：「送出的 JSON」已預填欄位，把 `null` 換成病人的數值（可放多筆，一次最多 1000 筆）
   影像模型：在「影像檔（DICOM、PNG、NIfTI…，可選多個）」選擇影像
5. 按「送出試呼叫（POST 端點）」，按鈕顯示「呼叫中…」
6. 出現「呼叫成功（推論紀錄 #N）。」與回應內容（JSON）

**要注意**

- 試呼叫用目前登入的帳號、經 Gateway 呼叫，與程式呼叫完全相同，也照樣寫稽核
- 自己不在分享對象中時，表單會先提醒「你（帳號）不在「…」的分享對象中，呼叫會被拒絕（403）…」
- 要給資訊人員的串接方式，在同頁展開「給資訊人員：程式呼叫方式」

### 情境 E5：訓練紀錄多了以後翻頁查詢

**角色**：有 Training 權限的研究員

專案跑了幾百次訓練，訓練紀錄頁一次全部載入很慢，也很難找到要的結果。

**操作步驟**

1. 「建模管理 → 訓練紀錄」，預設勾選「只看我送出的」；要看全專案的訓練就取消勾選（B-05）
2. 表格上方顯示「共 N 筆…，這一頁是第 a–b 筆（每頁 20 筆，由新到舊；依分數排序只排這一頁）。」
3. 超過 20 筆時，表格下方出現「上一頁」「第 p / 總頁數 頁」「下一頁」，按鈕翻頁
4. 要在這一頁內依分數排序，點欄位標題「主要分數（依分數排序）」；再點一次反向。點「編號（依時間排序）」回到依時間
5. 按「展開訓練 #N」查看細節

**要注意**

- 依分數排序只排目前這一頁；要找全專案最好的模型，先翻到各頁比較，或縮小範圍（勾選「只看我送出的」）
